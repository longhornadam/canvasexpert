# 1.0beta slice 00b — sweep apply hardening

Status: **QUEUED** (run after 00a is accepted)

Risk: **high** — grade-adjacent write boundary (`seconds_late_override` mutations).

Depends on: 1.0beta-00a accepted (no code dependency; sequencing only).

## Teacher-visible result

Applying a late-work sweep can no longer write whatever the browser submitted. The apply
step recomputes the sweep from authoritative Canvas state (or executes through the
operation-ledger sweep adapter) at apply time, so a stale preview tab, a modified request,
or drifted Canvas state cannot push wrong `seconds_late_override` values. Preview remains
fast and unchanged in appearance.

## Background (established truth)

`/api/sweep/apply` (`api/webui/routes/gradebook_sweep.py:29-53`) JSON-decodes the
browser-submitted `entries` form field and PUTs each row's `seconds_override` to Canvas
using client-supplied `assignment_id`/`user_id`, with no recompute and no drift check.
Meanwhile a complete `SweepAdapter` already exists at
`api/operation_ledger/adapters/sweep.py` with `build_payload`, `capture_baseline`,
`check_drift`, `freeze_review`, idempotency keys, `execute` (writes
`seconds_late_override`), `reconcile`, and receipts. The vision doc (§11.5, §13.4, §21
item 9) marks this a release blocker; the locked decision is to reuse the adapter, not
build a second recompute path.

## Locked design for this slice

Route sweep apply through the operation-ledger `SweepAdapter`.

1. The apply route stops trusting `entries`. It accepts the sweep **settings** (the same
   input `sweep_preview` takes) plus whatever review/confirmation token the ledger
   pattern requires, and drives the ledger sequence: build payload → capture baseline →
   drift check → freeze → execute → reconcile → receipt.
2. Browser-submitted entries may still be sent for **display-diff purposes only** (e.g.,
   to warn "Canvas changed since your preview"), never as the write set. If diffing is
   more than trivial, drop it and rely on the adapter's own drift check.
3. Preview (`/api/sweep/preview`) is unchanged.
4. Response shape to the frontend may change minimally; update the calling JS in the same
   slice so the sweep UI still completes end-to-end.
5. No new persistence, no schema changes, no mirror involvement — this is a live write
   boundary per design law 5.7.

Forbidden: keeping the direct-PUT path alive "for compatibility"; adding a second
recompute implementation beside the adapter's `_compute_sweep`.
