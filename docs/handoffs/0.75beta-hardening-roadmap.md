## Context — read this first, it corrects the previous framing

Date: 2026-07-15. **This code has never been used during a school year. It is not battle-tested,
it has no live users, and there is no schedule pressure.** Students arrive in ~35 days, but nothing
is deployed and nobody depends on it today. Earlier drafts of this roadmap wrongly framed the work
as protecting a running production system "mid-year" — delete that mental model.

The real goal: **use the clean pre-deployment window to get the code correct, debuggable, and
structurally honest before it meets reality for the first time.** First real use will surface bugs
no test caught — that is guaranteed — so the priorities are (1) correctness/data-integrity
invariants that must not be wrong on day one, and (2) enough observability to diagnose the first
real failures fast. Structural cleanup is cheap *right now* (no users to regress), so we do the
slices that pay off, but we **do not** speculatively refactor seams whose real-world failure modes
we haven't observed yet.

This program folds in an adversarial review (Codex) that read the current code and corrected two
real errors in the prior roadmap (see Workstream 0). Its architectural thesis is adopted with one
change: MCP should become a first-class adapter over shared application services rather than
reaching through the web layer — but only the **MCP-facing** slice of that extraction is in scope
now; the full route-layer refactor is deferred until real usage shows where it hurts.

## Locked decisions (do not reopen)

- **No rewrite, no new language.** Python stays; the maintainer's Python literacy is the human QA
  layer over AI-authored changes. Maintenance is AI-directed ("guardrail curator"): every fix
  leaves a test behind; prefer invariants enforced by code/tests over invariants enforced by memory.
- **Hard product constraints (unchanged):** single-ZIP, userspace-only, **no admin ever**; Canvas
  PAT only in keyring (`quizforge-api`); local-only `127.0.0.1` bind, no public routes; pseudonymize
  before any external transmission.
- **Storage stays JSON.** No SQLite/ORM at this stage — it would add more debt than it removes.
- **`engine/` is QuizForge** — proven, decoupled, out of scope. Do not refactor it.
- **MCP write tools are out of scope for 0.75b.** When they come, they route through existing
  authorities (operation ledger for reversible Canvas ops; PowerGrader sessions/policy/receipts for
  grading). Never a generic "call any Canvas endpoint" tool.
- **No frontend build system.** Plain JS supports the ZIP/no-admin requirement.
- Environment: Windows, Python 3.14 via `py`, branch `dev`, tests `py -m pytest api/tests`; risk
  tiers and escalation per `AGENTS.md`.

## Sequencing principle (the one rule that governs decomposition)

**Nets before trapeze.** The correctness invariants and the MCP contract (Workstream A + C.1) are
prerequisites for the refactors (C.2, D). Do not land a structural refactor before the tests that
would catch its regressions exist. Concretely:

```
0 (quick verified fixes)
      │
      ▼
A (correctness + data-integrity nets)  ──►  B (observability)   [B.1 can start anytime]
      │
      ├──► C.1 (MCP contract + schema tests)  ──►  C.2 (MCP-facing use-case extraction)   [C.2 needs A.1]
      │
      └──► D (legibility refactors)   [D.1 broad; D.2 feeds C.3]
                                      C.3 (Connections page)   [needs B.3 + D.2]
```

## Workstream A — Correctness & data-integrity nets (high; prerequisite for refactors)

**A.1 Cross-process-safe persistence for the private stores.** *(Risk: high · Effort: medium)*
Now mandatory: the MCP server is a **separate writer process** alongside the web UI and the routines
thread. The ledger already has the right primitives — interprocess lock + flushed temp + atomic
replace ([operation_ledger/storage.py:23](api/operation_ledger/storage.py:23),
`operation_ledger/file_lock.py`). Other stores don't: vault and settings use load/mutate/save
snapshots; PowerGrader sessions ([session_store.py:21](api/powergrader/session_store.py:21), confirm
line) and the autoscore queue use process-local locks + direct overwrite; the legacy activity log
uses unlocked read-append-write.
- **Approach:** extract the ledger's atomic-JSON primitive into neutral storage support, then give
  each store its own transaction — vault: lock→reload→mutate→atomic-save; settings: lock the whole
  read-modify-write; PowerGrader: per-session interprocess transaction; autoscore: queue-level
  transaction. **Do not** rewrite the ledger adapters (their complexity is essential/contract-backed).
- **Done:** an interleaved-writers test shows no lost vault pseudonym; existing suites green.

**A.2 One enforced external-AI transmission boundary.** *(Risk: high · Effort: medium)*
Today `openrouter_client.score()` ([openrouter_client.py:388](api/openrouter_client.py:388)) relies
on every caller remembering to run `scan_payload` first; several live and retired sites own that
obligation independently. Replace the convention with a chokepoint every caller (and future
MCP-driven scoring) must pass: accept bundle+vault → run the safety gate
([feedback_safety.py::scan_payload:37](api/feedback_safety.py:37)) → budget/model checks → provider
transport → emit a sanitized operational event. Keep provider request-building in
`openrouter_client.py`; centralize only the *authorization to transmit*.
- **Done:** all send sites go through the boundary; a test proves an unsafe bundle cannot reach the
  transport.

**A.3 Invariant tests for what a human can't eyeball.** *(Risk: high · Effort: low-medium)*
The net that makes C.2/D safe to attempt. Pin: no student PII in any outbound payload (MCP tools +
the A.2 boundary — extend the MCP no-PII sweep to the scoring path); vault survives concurrent writes
(A.1); vault at rest expectations (if 0.x/later encryption is added). Each invariant fails loudly on
regression.

**A.4 (Optional, low-priority) Localhost CSRF middleware.** *(Risk: low-effort hardening)*
Deprioritized per the maintainability-over-edge-security steer and the no-users reality, but it's
*also cleaner code*: promote the existing origin check
(`webui/local_request_guard.py::require_local_mutation`) into one middleware over unsafe methods and
delete the two scattered per-route hookups. The `Form(...)`→JSON migration stays **out of scope**.
Do it if convenient; it is not gating.

## Workstream B — Observability (make first real contact debuggable)

**B.1 App version / build stamp.** *(Risk: low · do early)* There is none today. Single `__version__`
surfaced in UI, logs, and the support bundle. Bump on release.

**B.2 PII-free operational logging.** *(Risk: high — FERPA-adjacent · Effort: medium)* Structured,
rotating, local-only: what workflow ran, which step failed, Canvas HTTP status/timing, error class —
never payloads, never names. Enforce PII-free **by construction** by routing log records through the
same discipline as A.2. This is the primary enabler for diagnosing first real failures.
- **Done:** a failing Canvas call yields a readable, name-free log line; a test proves no vault
  identifier can appear in a record.

**B.3 One-click support / diagnostics bundle.** *(Risk: medium · Effort: medium)* Gather B.2 logs +
`__version__` + an environment/health snapshot (token set? catalog present? WebView2? workspace
writable? proxy? server import succeeds? tool-schema version?) into one sanitized zip. Reuse the
field diagnostic already validated on a real district laptop.
- **Done:** exports, contains no PII (tested), enough to triage a typical failure without a live call.

**B.4 Resolve the legacy activity log.** *(Risk: medium)* [activity.py:19](api/webui/activity.py:19)
writes a synced `activity_log.json` with titles/courses/URLs/free-form detail; no browser script
appears to consume `/api/activity`. Determine real usage: if unused, remove and derive activity from
receipts/routine results; if used, rename and classify it as a **PRIVATE** teacher feed. It must
**not** be conflated with the B.2 sanitized support log — two things called "logs" with different
privacy contracts is debt.

## Workstream C — MCP as a first-class interface

**C.1 Durable MCP tool contract + schema tests.** *(Risk: medium · precedes any tool expansion)*
Treat existing tool names and required parameters as a public interface; add schema tests and a
tool-schema version. Rationale: heterogeneous clients connect incompatibly and at least one
(ChatGPT Work, per OpenAI's documented remote-connection model) may freeze approved schemas until an
admin refresh — so a stable contract matters more than automating any one config format.
- **Done:** schema tests fail if a tool's name/required params change without a version bump.

**C.2 Extract the MCP-facing use cases (the one structural slice to do now).** *(Risk: high · needs A.1)*
Fix the backwards-ownership: [mcp_server/tools.py](api/mcp_server/tools.py) currently imports private
helpers from `webui.routes.gradebook_common`, `gradebook_snapshot`, `names`, `roster_canvas` — the
integration layer depending on the presentation layer. Extract only the use cases with multiple
consumers into application services that **both** routes and MCP call: current-course authorization;
roster acquisition + vault sync; assignment/submission acquisition; gradebook snapshot construction;
identity-safe MCP projections. Routes and MCP tools become thin translators around these.
- **Do not** build a generic service framework, repository layer, or DI container.
- **Done:** MCP imports nothing from `webui.routes`; routes + MCP share the extracted services; A.3
  invariants still green.

**C.3 Connections page — "Connect an AI assistant."** *(Risk: medium · needs B.3 + D.2)*
A dedicated page (not Settings bloat), three explicit recipes, not a generic plugin framework:
- **Claude card:** produce/download a `.dxt` desktop-extension bundle; show install/restart/status;
  retain a manual stdio snippet.
- **ChatGPT Work card:** explain plan/admin requirements, the remote/Secure-MCP-Tunnel setup, tool
  scan, and connection status.
- **Generic MCP card:** path-resolved stdio config.
- **Shared health checks:** version, Python/interpreter path, token configured, workspace available,
  server import succeeds, tool-schema version (reuse B.3 + the D.2 path resolver).
One-button behavior where the client supports it; instructions + diagnostics as the fallback. Must
**not** mount/start the server in the web process, and any config file it writes for a client must be
non-destructive and idempotent (it writes a user-owned file; no admin).
- **Done:** a teacher connects Claude Desktop without hand-editing JSON; existing client servers are
  preserved; a clear not-configured state shows when preconditions fail.

## Workstream D — Legibility for AI-directed maintenance (low-medium; high leverage for the maintainer)

**D.1 Normalize imports.** *(Risk: medium · Effort: medium)* Eliminate the 27 `except
ModuleNotFoundError` `webui.*`/`api.webui.*` dual guards + scattered `sys.path` edits. Entry points
(`qf_ui.py`, the MCP `__main__.py`) establish repo root once; application code imports consistently
through `api.*`. Prevents duplicate module-level state and the two-execution-models-per-file tax that
slows every AI session. Migrate standalone legacy CLI scripts separately only if needed.

**D.2 Runtime path/workspace resolver.** *(Risk: low-medium · feeds C.3 and 0.1)*
[deps.py:86](api/webui/deps.py:86) captures workspace-derived paths at import time, but onboarding can
change the workspace afterward. Replace mutable constants (`AI_TA_DIR`, `RUBRIC_FOLDERS`, folder
lists) with runtime resolver functions owned in one place: current workspace paths, content-library
folders, AI-TA/rubric sources, and the runtime interpreter/install paths that C.3's connection
instructions need. A small concrete path service — **not** a general environment abstraction.

**D.3 Keep the maps honest.** *(Risk: low)* Update `docs/reference/*-module-map.md` + `AGENTS.md` as
seams move; auto-generate or delete the stale line-count snapshots. These are the AI's navigation and
directly set debug speed.
