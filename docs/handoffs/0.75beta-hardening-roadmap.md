# Execution brief: 0.75beta — safe to run, possible to debug during the school year

Status: **ready for implementation** (roadmap — cut individual briefs from the items below)

Risk: **high** (spans FERPA, credentials, and data integrity; individual items vary — noted per item)

Executor: **Luna** for the contained items, **Terra** for the observability + concurrency items (cross-cutting)

---

## Outcome

Treat the current codebase as **0.5beta**: it works, it has 749 passing tests, and its product
instincts are sound. 0.75beta is **not** new features and **not** a rewrite. It is the hardening
pass that makes the app *safe to run in front of real teachers* and *possible to debug remotely
when something breaks mid-year* — because the maintainer is solo and directs changes through an AI
agent (the "vibeseat"), not by reading every line.

The theme, in one line: **close the silent-corruption landmines, gain eyes into what's happening,
and lock the guardrails so a mid-year fix can't quietly start a new fire.**

## Locked decisions (context a fresh session needs — do not reopen)

- **No rewrite, no new language.** Python stays. The maintainer's Python literacy is the human
  QA layer over AI-authored changes; a rewrite would remove it. Decided after explicit analysis.
- **Maintenance model is AI-directed ("guardrail curator").** Every fix should leave a test
  behind. Prefer changes that are *enforced by code/tests* over changes that rely on remembering.
- **Hard product constraints (unchanged):** single-ZIP delivery, userspace-only install, **no
  admin rights ever** (see [[project-no-admin-zip-delivery]] in maintainer memory); Canvas PAT
  lives only in keyring (`quizforge-api` service); local-only, `127.0.0.1` bind, no public routes;
  pseudonymize-before-any-external-transmission (feedback-scoring contract).
- **`engine/` is QuizForge** — proven, decoupled (imports nothing from `api/`), gospel. Do not
  refactor it as part of this work.
- **In-flight:** the read-only MCP server (`api/mcp_server/`, see
  `docs/handoffs/mcp-read-only-server.md`) is **uncommitted on `dev`, tests green, awaiting the
  maintainer's diff review.** The working tree also carries concurrent PowerGrader
  interactive-auto-post work. A fresh session must not assume a clean tree and must not revert
  either body of work.
- Environment: Windows, Python 3.14 via `py`, branch `dev`, tests via `py -m pytest api/tests`.
  Risk tiers, escalation, and verification expectations per `AGENTS.md`.

## The greatest needs, prioritized (three pillars)

Ranked for the stated goal: surviving live use and remote debugging during the school year.
Each item is a mini-brief; cut it into a full `HANDOFF_TEMPLATE.md` brief when it's picked up.

### Pillar 1 — Close the data landmines (do first; these cause baffling live bugs)

**1.1 Localhost CSRF — one boundary check.** *(Risk: high · Effort: low · highest value)*
Any webpage a teacher visits can `POST` to `http://127.0.0.1:8765/...` and rewrite the Canvas
token or settings; 19 route modules accept form-encoded bodies and only 2 of ~44 carry the
existing guard (`api/webui/local_request_guard.py::require_local_mutation`).
- **Approach:** promote the origin check into a single middleware over all unsafe methods
  (POST/PUT/PATCH/DELETE) that rejects any request whose `Origin`/`Referer` isn't the app's own
  origin. This needs no per-route edits and likely no frontend change (the guard header is already
  sent). Delete the now-redundant per-route guard hookups in `work.py`/`operations.py`.
- **Defer (optional, separate):** migrating the 19 `Form(...)` modules to JSON bodies is
  *hardening on top*, touches backend + JS, and is roughly line-neutral — not part of the freebie.
  The middleware alone closes the vulnerability.
- **Done:** one test fires a cross-origin POST and asserts rejection; app functions unchanged.
- Does **not** touch the MCP server (stdio, no HTTP surface).

**1.2 Identity vault at rest — encrypt and de-sync.** *(Risk: high · Effort: low-medium)*
`_System/Identity Vault/vault.json` is the plaintext pseudonym→real-name/Canvas-ID/SIS-ID decoder
ring, written to a OneDrive-synced path — it undoes all outbound pseudonymization and replicates
to the cloud.
- **Approach:** encrypt at rest with Windows DPAPI (per-user, no admin, no key management) and/or
  relocate the vault out of the synced workspace root (e.g. `%LOCALAPPDATA%`, like the launcher's
  deps marker). Preserve the `Vault` API (`api/feedback_vault.py`) so callers are unaffected.
- **Done:** vault file is unreadable as plaintext; `get_or_assign`/`reverse` round-trip intact;
  migration of an existing plaintext vault handled on first load.

**1.3 Concurrent writes — one locked, atomic persistence path.** *(Risk: high · Effort: medium)*
`vault.json` and `settings.json` have no lock and no atomic write ("last-writer-wins"). There are
now **three** potential writers — the web UI, the routines heartbeat thread, and the new MCP server
(every roster/submission/gradebook call does `get_or_assign` + `save`). Two near-simultaneous
pseudonym assignments can silently drop one → a pseudonym that no longer reverses → a teacher who
can't re-identify a student, with no error and no log. This is the archetypal miserable-to-debug
mid-year bug, and the MCP server raised its likelihood.
- **Approach:** route vault + settings writes through the existing cross-process lock + atomic
  rename already used by the ledger (`api/operation_ledger/file_lock.py`,
  `api/course_catalog.py`'s tempfile+`os.replace` pattern). One shared helper every writer uses.
- **Done:** a concurrency test (interleaved writers) shows no lost pseudonym; existing suites pass.

### Pillar 2 — Gain eyes (you cannot debug the school year blind)

**2.1 App version + build stamp.** *(Risk: low · Effort: trivial · do this first, it's free leverage)*
There is no version number anywhere. With teachers on different ZIPs/pulls you cannot answer "what
version are you on?"
- **Approach:** a single `__version__` surfaced in the UI footer/About, in logs, and in the support
  bundle (2.3). Bump on release.

**2.2 PII-free operational logging.** *(Risk: high — FERPA-adjacent · Effort: medium · biggest new capability)*
Today, when a teacher says "it didn't work," there is nothing to read: audits are counts-only
(correct) but there is no operational error log. This is *the* enabler for remote troubleshooting.
- **Approach:** structured, rotating, local-only log of *what workflow ran, which step failed,
  Canvas HTTP status/timing, error class* — never payloads, never names. Enforce PII-free **by
  construction**: run log records through the same discipline as outbound payloads
  (`api/feedback_safety.py::scan_payload`) so a careless future edit can't leak a name into a log.
- **Done:** a failing Canvas call produces a readable, name-free log line; a test asserts no vault
  identifier can appear in a log record.

**2.3 One-click support bundle / self-diagnostic.** *(Risk: medium · Effort: medium)*
Turn "20 questions over email" into "teacher clicks Export Diagnostics and sends you a file."
- **Approach:** gather the PII-free logs (2.2), `__version__` (2.1), and an environment/health
  snapshot — token set? catalog present? WebView2/runtime? workspace path writable? proxy? — into
  one sanitized zip. Reuse the environment-characterization checks from the field diagnostic
  (admin/AppLocker/WDAC/WebView2/proxy) already validated against a real district laptop.
- **Done:** bundle exports, contains no PII (tested), and is enough to triage a typical failure
  without a live session.

### Pillar 3 — Lock the guardrails (so mid-year fixes don't cause new fires)

**3.1 Invariant tests for the things a human can't eyeball.** *(Risk: high · Effort: low-medium · highest regression value)*
The vibeseat's safety net. Add/confirm tests that permanently pin the non-negotiables:
- no student PII in **any** outbound payload (MCP tools + OpenRouter path) — extend the MCP
  no-PII sweep pattern to the OpenRouter send path;
- CSRF middleware rejects cross-origin mutations (1.1);
- vault survives concurrent writes (1.3);
- vault at rest is not plaintext (1.2).
- **Done:** each invariant has a test that fails loudly if a future session regresses it.

**3.2 Legibility / entropy pass — reduce wrong-file risk under pressure.** *(Risk: low · Effort: medium)*
Retired-feature shims (`api/feedback_pipeline.py` facade, the FeedbackExpert workspace-alias layer
in `workspace.py`) and `quizforge`/`qf_` remnants make navigation ambiguous — raising the chance an
AI session edits the wrong file when you're debugging under time pressure. Do the cleanup *before*
the school year, not during.
- **Approach:** guarded consolidation, one subsystem at a time, tests green throughout; give each
  removed shim a deprecation note rather than a silent delete. Keep the `docs/reference/*-module-map.md`
  files and `AGENTS.md` current as you go — they are the AI's navigation and directly set debug speed.
- **Note:** the keyring service name `quizforge-api` is load-bearing (stores live tokens) — renaming
  it needs a migration; treat as out of scope for a cosmetic pass.

**3.3 (Optional foundation) CI on push.** *(Risk: low · Effort: low)*
Run the existing suite + a linter automatically so no mid-year fix relies on remembering to run
pytest. Lower urgency for a solo local project than Pillars 1–2, but cheap insurance. Requires a
minimal GitHub Actions workflow; keep it green-or-block.

### Pillar 4 — Make built capabilities reachable (feature completion, not hardening)

**4.1 The MCP connect experience — "Connect an AI assistant."** *(Risk: medium · Effort: medium · top MCP-related priority)*
The read-only MCP server (`api/mcp_server/`) is built and tested, but a teacher can only connect it
today by hand-editing their AI client's JSON config (e.g. `%APPDATA%\Claude\claude_desktop_config.json`)
and restarting the app. That is too hard for the target teacher and fails *silently* — a trailing
comma, wrong path, escaped-backslash mistake, or unresolved `py` produces no error, just tools that
never appear. Until this is solved, the MCP server has no realistic path to a teacher; the feature
is effectively unshipped.
- **Approach:** add a read-only **"Connect an AI assistant"** page to the web UI that does the
  registration *for* the teacher rather than showing a snippet to copy. CanvasExpert already knows
  the two things the teacher can't easily get right — its own install path and where `py` resolves —
  so a **"Connect Claude Desktop"** button writes/merges the correct server block into the client's
  config file (create-if-missing, **merge don't clobber** existing servers, absolute path pre-filled),
  then tells the teacher to restart the client. Show a health line reusing the existing
  token-is-set check and `__version__` (ties to 2.1).
- **Scope discipline:** connection differs per client (Claude Desktop = config file / Desktop
  Extension; Claude Code = `claude mcp add`; ChatGPT / Cowork = their own connector). Do **not** try
  to one-click every client. Make **Claude Desktop** a real button; provide a path-pre-filled
  copy-paste snippet as the fallback for the long tail.
- **Constraints:** fully userspace — it writes a file the user already owns in their own AppData,
  no admin. It must **not** mount or start the MCP server inside the web process (the stdio-only,
  not-in-FastAPI decision stands); it only writes the *client's* config. In-assistant discovery and
  trust are already handled by the FERPA tool docstrings, so this item is purely the registration
  handshake.
- **Sequencing:** highest priority *among MCP work*, but still after the Pillar 1 safety landmines —
  don't make the server easier to reach before the concurrency/vault fixes land, since MCP calls are
  a vault writer.
- **Done:** teacher clicks Connect, restarts the client, and the tools appear; the config merge
  preserves any pre-existing MCP servers and is safe to run twice (idempotent); a clear
  "token not set" / "not connected" state is shown when preconditions aren't met.
- **Risk note:** medium because it writes into *another application's* config file — the merge must
  be non-destructive and reversible; back up or round-trip the existing JSON before writing.

## Out of scope

- Any v2 rewrite, language change, or new architecture. New user-facing features unrelated to
  hardening. Refactoring `engine/`/QuizForge. Changing PAT storage. Making the app network-reachable.
  The `Form(...)`→JSON migration (1.1) is explicitly *deferred*, not part of the CSRF fix.

## Reference pattern and routing

- CSRF guard to promote: `api/webui/local_request_guard.py::require_local_mutation`
- Cross-process lock + atomic write to reuse: `api/operation_ledger/file_lock.py`;
  atomic-rename pattern in `api/course_catalog.py` (tempfile + `os.replace`)
- Outbound PII gate to reuse for logs/tests: `api/feedback_safety.py::scan_payload`; vault at
  `api/feedback_vault.py` (`get_or_assign`, `reverse`, `all_real_identifiers`)
- Test pattern: `api/tests/test_gradebook_routes.py` (monkeypatch module-level fetchers,
  fabricated generic names, `tmp_path`, worktree-independent)
- Field diagnostic already validated on a real district laptop (no admin; AppLocker present but
  empty policy; WDAC user-mode off; WebView2 present; direct outbound) — reuse for 2.3.
- Read `AGENTS.md` and the relevant `docs/reference/*-module-map.md` before broad inspection.
