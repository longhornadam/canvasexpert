# 1.0beta slice 01b — assignment deletion membership filtering and safe orphan cleanup

Status: **GREEN; completed — senior accepted** (uniform shrink guard across both passes
ratified; one-pass prune deferral ratified as a safe reading of "defer to the daily full
pass" — the index commit already gives immediate read correctness)

Risk: **high** — touches private submission storage enumeration and adds a pruning path;
FERPA persistence rules apply.

Depends on: 1.0beta-01a accepted.

## Teacher-visible result

Deleting an assignment in Canvas removes it from every Canvas Expert query promptly after
the next delta — gradebook, work rows, reports, and MCP reads stop showing its
submissions. Today the deletion can remain invisible until the next full pass (up to 24h),
because aggregate reads enumerate submission files on disk rather than the committed
assignment index. The live change test that failed to surface a deletion (vision §3.1)
must pass after this slice.

## Background (established truth)

- Delta rewrites the assignment index (`api/mirror/sync.py` ~179, `store.write_assignments`
  full replace) but never prunes submission files; pruning happens only in `full_pass`
  (`sync.py` ~130, `store.prune_submission_files` ~431).
- Aggregate reads enumerate by directory listing: `course_submissions`
  (`api/mirror/queries.py` ~66-76) iterates `store.list_submission_assignment_ids` =
  `os.listdir` (`store.py` ~468-473) — unfiltered by the index.
- Inverse hazard (vision §10.1, §21 item 14): the mirror writes any non-error empty
  assignment collection as authoritative and full-pass pruning then deletes all
  submission files. `canvas_client._canvas_get_all` follows pagination; this slice must
  make "complete collection" an explicit precondition for destructive effects.

## Locked design for this slice

### 1. Membership filtering at read time (the correctness fix)

`course_submissions` and `assignment_submissions` filter by the committed assignment
index: enumerate submission files, then drop any `assignment_id` not present in the
current index. Missing/corrupt index behaves as today (last-good rules); filtering only
ever narrows, never invents. ID comparison uses the existing normalized string form.

### 2. Completeness gate before destructive effects

Define collection completeness explicitly: `write_assignments` may replace the index (and
any pruning may run) only when the fetch returned without error — which, given
`_canvas_get_all`'s all-or-error shape, is the current success condition made explicit.
Add a guard: if the new collection is empty **or shrinks by more than 50%** versus the
previous index, write the index (deletion is legitimate) but record a sanitized
`large_shrink` diagnostic count. Pruning of submission files for a shrink beyond that
threshold is deferred to the daily full pass; filtered reads already provide logical
correctness. This implements "filtering provides immediate correctness; pruning controls
clutter" (vision §10.2).

### 3. Prune on delta, safely

After a successful delta index commit, prune orphan submission files whose IDs left the
index, under the existing `prune_submission_files` path-validation rules, subject to the
shrink threshold above. Never touch anything outside the mirror submissions directory;
never touch evidence, receipts, or vault data.

### 4. Change diagnostics

Record sanitized counts (added/changed/removed assignment IDs; orphan files filtered;
orphan files pruned) in the existing sync summary so the live change test can assert a
deletion was observed.

## Execution result

**Traffic light: GREEN**

Preflight confirmed all stated facts, including the key stop condition: `_canvas_get_all`
(`api/webui/canvas_client.py` ~58-89) has no partial-success return shape — it loops the
`Link` header internally and returns either the fully concatenated list with no error, or
`(None, error)`. No RED condition. Also checked every current consumer of
`course_submissions`/`assignment_submissions`/`list_submission_assignment_ids`
(`work_registry/providers`, `gradebook_curves.py`, `mirror_reads.py`, `powergrader/canvas_fetch.py`,
`gradebook_snapshot.py`, `operation_ledger/adapters/curve.py`) — none intentionally reads a
deleted assignment's orphaned submission history, so no consumer-dependency RED either.

**Implementation:**

1. Membership filtering (`api/mirror/queries.py`): `course_submissions` and
   `assignment_submissions` now read the committed assignment index first and drop any
   `assignment_id` not present in it, using the existing normalized string ID form. A
   missing/corrupt index behaves exactly as before — `course_submissions` still returns
   `MIRROR_UNAVAILABLE` (unchanged early-return), and `assignment_submissions` does not gate
   on the index at all when it's absent (last-good rules unchanged), only when it's present
   and no longer lists the id.
2. Completeness gate + shrink guard (`api/mirror/sync.py`): new `_is_large_shrink()` and
   `_commit_assignment_index()` helpers. The index always commits on an error-free fetch
   (already true — both passes return early on fetch error before ever calling this). An
   empty or >50%-shrunk new collection vs. the previous committed index still commits, but
   submission-file pruning defers to the next pass (whose baseline is now the smaller
   committed index, so a genuine shrink self-heals to a normal prune one pass later; a
   transient dip never prunes on it).
3. Delta pruning (`api/mirror/sync.py`): `delta_pass` now calls the same guarded prune path
   `full_pass` already had — previously delta never pruned at all. Both passes now share one
   helper instead of duplicating the write+prune sequence; `full_pass`'s previously
   unconditional prune is now itself subject to the same guard (closes vision-doc item 14,
   which the vision doc says to fold into this slice).
4. Diagnostics: both pass summaries gained `assignment_changes` = `{added, changed, removed,
   large_shrink, orphans_filtered, orphans_pruned}` (assignment-ID-only, sanitized).
   `full_pass`'s existing `pruned_assignments` key is preserved (now sourced from the same
   diagnostics dict) so no existing caller shape broke.

No changes were needed in `api/mirror/store.py` — `write_assignments` and
`prune_submission_files` already had the right primitives; the gate/guard/diagnostics logic
lives in the sync-pass orchestration layer that already reads-before-writes.

**Files changed:**
- `api/mirror/queries.py` — membership filtering, item 1.
- `api/mirror/sync.py` — completeness gate, shrink guard, delta pruning, diagnostics (items 2-4).
- `api/tests/test_mirror_queries.py` — 2 new tests (orphan filtering for both read functions).
- `api/tests/test_mirror_sync.py` — 4 new tests (immediate exclusion before prune, exact
  delta prune, empty-collection commit, large-shrink defer + one-pass-later self-heal) plus
  an explicit fetch-error-changes-nothing test.

**Verification:**

- Adjacent consumer suites (`work_providers_mirror`, `gradebook_curves`-adjacent, mcp,
  `powergrader_mirror_session`, `gradebook_routes`) → 65 passed.
- Full `py -m pytest api/tests -q` → 905 passed, 1 skipped, 3 failed. Confirmed the 3

**Deviations:** none from the locked design. One naming choice not dictated by the brief:
`large_shrink` in the diagnostic is the sanitized *count* of removed IDs when the guard

unconditional prune should also honor the shrink guard — was resolved in favor of applying it
uniformly, since vision-doc item 14 explicitly names the full-pass prune as the destructive
hazard this slice's completeness gate must close, and the brief instructs folding item 14 in.
