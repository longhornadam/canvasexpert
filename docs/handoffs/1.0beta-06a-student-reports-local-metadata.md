# Migrate Student Reports' per-student packet to local metadata + focused evidence

Status: **READY**

Risk: **medium** - read-only migration of a teacher-initiated, non-Canvas-mutating report
generator; the existing live fetch is preserved as the fallback path, not deleted.

Depends on: source HEAD `e40a2c0` (Batch 2 fully closed; Batch 5 is next per
`docs/handoffs/NEXT_BATCH.md`)

## Teacher-visible result

Generating a Student Report packet (`/students/reports`, "Standing/Late/Adjustments/Comments"
sections) for a student whose courses' private mirrors are current makes **zero Canvas calls**
for any of that metadata — it reads exactly what Gradebook/Roster/Course Info already trust.
Work-sample attachments still require a live fetch, but only for the one submission that
actually has a file to download, not the whole course's submissions. When a course's mirror
isn't current, the report falls back to exactly today's live fetch for that course, unchanged
— nothing that works today stops working.

One visible, deliberate content change: comments authored by staff now show a role label
("Instructor") instead of the commenter's name, matching a privacy rule the private mirror
already applies everywhere else (comments have never stored author names — see Background).
A student's own comments still show the student's own name, since the report already knows it.

## Background (read before writing code)

Vision doc §17.2 "Former Program 7 — migrate Student Reports and portfolios" (~lines
1375-1390): *"eliminate duplicate large metadata fetches from report generation... assemble
roster, assignment, standing, text, attempt, comment, group, and due facts from the typed read
service... remove routine direct `requests.Session` calls from report/portfolio code."* §11.7
(~lines 870-881): *"local spine: roster identity, assignments, submission standing, text
bodies, attempts, comments, group names, personalized due facts... focused Canvas/evidence:
attachment bytes, signed download URLs in memory... split current direct `requests.Session`
collection code into local metadata assembly plus focused evidence acquisition."* §7.3
(~lines 454-459): *"CanvasMirror coordinates [attachment/evidence] status... it does not turn
the heartbeat into a course-wide download job."*

Today, `api/student_packet.py::build_packet` opens its own `requests.Session()` (line 143) and
paginates the **whole course's** submissions for one student on every run — even though the
private mirror (`api/mirror/store.py`, Batch 1's typed read service in
`api/mirror/read_service.py`) already stores everything this report needs **except** file
attachments and the `url` field of an `online_url` submission, which are deliberately never
cached (signed URLs are never persisted, per the mirror's own design law).

**Senior decisions already made for this slice (do not revisit):**
- Reports keep their own narrow, focused per-submission fetch for attachments — this brief does
  **not** route through PowerGrader's `api/powergrader/canvas_fetch.py` evidence machinery.
  Confirmed: no code changes to anything under `api/powergrader/`.
- Staff-authored comments show a generic role label, not a name. A student's own comments show
  the report's own known `student_name`. This is the resolution to comments never having stored
  author names in the mirror to begin with (`api/mirror/store.py:557-569`'s `_comment_record`,
  its own comment: *"Role label only — still no names, avatars, or attachments"*) — not a new
  privacy reduction this brief introduces.
- This brief covers only `api/student_packet.py::build_packet` (the single-student,
  multi-course packet, used by both the interactive `/api/student-packet/stream` route and the
  `_run_routine_student_reports` built-in routine, which calls `build_packet` directly). The
  parallel migration of `api/portfolio_service.py::build_merged_portfolios` (single-course,
  multi-student cohort portfolios) is deliberately deferred to a follow-up brief that reuses
  this brief's new shared helpers — do not migrate it here.
- `api/webui/routes/reports.py::list_assignments_full` (the assignment-picker endpoint) is
  **not** touched by this brief — its rich shape (quiz detection, assignment-group names) has
  no equivalent yet in either `private_assignments` or Course Catalog's assignment scope, and
  closing that gap needs its own dedicated investigation, not a drive-by schema change here.
- The private source/freshness provenance manifest named by the vision doc is a separate,
  later, additive follow-up brief — not part of this one.

## Acceptance criteria

- [ ] `api/mirror/store.py::normalize_assignment` gains a new `description` field (the
  assignment's HTML instructions/prompt text, same permissive-string handling as the existing
  `body` field) — additive only; every existing field and caller is unaffected.
- [ ] `api/mirror/store.py::normalize_submission`'s `current` dict gains a new `url` field (the
  student's submitted URL for an `online_url` submission type, plain text — not a signed Canvas
  download URL, same sensitivity class as the already-stored `body`) — additive only.
- [ ] A new `api/submission_transport.py::fetch_submission(session, base, course_id,
  assignment_id, user_id)` function performs one focused, live Canvas fetch of exactly one
  student's one submission (for its current `attachments` list), returning `None` on any
  failure rather than raising — never a whole-course call.
- [ ] A new shared module assembles one course's joined assignment+submission records from
  `api/mirror/read_service.py` (`private_assignments`, `private_submissions`) in the same nested
  shape `build_packet`'s existing code already expects (`s["assignment"]`, `s["score"]`, etc.),
  when — and only when — both envelopes report `state == "current"`. When either is not
  current, the course is reported as needing the existing live fallback instead — the local
  path is never used with incomplete/stale data.
- [ ] `build_packet` uses the local path per course when available; when not, it falls back to
  exactly today's existing live `_get_all_pages` whole-course fetch for that one course,
  unchanged. A course that is local-current makes no whole-course Canvas call at all.
- [ ] For a local-current course, a live focused call via `fetch_submission` happens only for
  submissions whose `submission_type == "online_upload"` (the only type that can carry file
  attachments) and only when the "work" section is requested — never for `online_text_entry`
  or when "work" isn't in `sections`. A `requests.Session()` is constructed lazily, only the
  first time such a call is actually needed for a given `build_packet` run.
- [ ] A report that requests no attachments (either no "work" section, or a course whose
  submissions are all `online_text_entry`/`online_quiz`/ungraded with no upload) and whose
  every course is local-current makes **zero** Canvas calls — proven by a test asserting no
  Canvas-calling function is invoked.
- [ ] Comment display: for each `submission_comments` entry, if `author_id` matches the
  report's own `user_id`, the label is the report's own `student_name`; else if the comment's
  role (reusing the exact staff-role vocabulary already defined in
  `api/work_registry/providers/home_attention.py`: `_author_role`/`_PROVEN_STAFF_ROLES` —
  `{"admin", "administrator", "instructor", "staff", "ta", "teacher", "teaching_assistant"}`)
  is a proven staff role, the label is a generic role string (e.g. "Instructor"); otherwise the
  name is omitted entirely (no blank "— :" prefix) rather than guessed at.
- [ ] Every existing `_info_blocks`/`_signature`/"work"-section/manifest-dedupe behavior is
  otherwise unchanged — same DOCX output shape, same file-naming, same `_manifest.json`
  change-detection semantics, for both the local and live-fallback paths.
- [ ] The named acceptance gate passes.

The executor reports evidence; the senior accepts only when every criterion holds.

## Locked decisions

- **Schema additions** (`api/mirror/store.py`):
  - `normalize_assignment` (~lines 522-536): add `"description": row.get("description") if
    isinstance(row.get("description"), str) else ""` to the returned dict, matching `body`'s
    existing permissive-string pattern.
  - `normalize_submission` (~lines 572-616): add `"url": row.get("url") if
    isinstance(row.get("url"), str) else ""` to the `current` dict (~line 583-608), alongside
    the existing `body` field. Do not touch `_attempt_record`/`_comment_record`/the `attempts`
    dict — this brief does not consume attempt history (no current caller needs it; do not add
    it speculatively).
- **New focused fetch** (`api/submission_transport.py`): add `fetch_submission(session, base,
  course_id, assignment_id, user_id) -> dict | None`, modeled on this file's existing
  `get_all_pages`/`download_binary` style (thin wrapper over a caller-supplied session, no
  session construction inside it). Hits Canvas's single-submission endpoint
  (`{base}/api/v1/courses/{course_id}/assignments/{assignment_id}/submissions/{user_id}`) to
  get that submission's current `attachments` list. Returns `None` on any non-200/transport
  failure — never raises, matching this module's existing style (its two current functions do
  raise via `response.raise_for_status()`; this new function must catch that and any transport
  exception itself and return `None`, since a missing/failed focused fetch must degrade to "no
  attachments found" for that one work sample, not abort the whole report).
- **New shared module** `api/report_local_reads.py` (or fold into `api/student_packet.py` if,
  after reading both files, a separate module proves to add more indirection than value for
  this single-consumer slice — senior prefers a separate module since the deferred
  `portfolio_service.py` follow-up will need the identical joining logic, but the executor may
  return YELLOW with a one-line justification if a shared module is clearly premature for this
  slice alone):
  - A function assembling, for one `course_id`, the joined per-submission records this report
    needs: read `read_service.private_assignments(course_id, max_age_hours=None)` and
    `read_service.private_submissions(course_id, max_age_hours=None)`; if either envelope's
    `state != "current"`, return a sentinel meaning "use the live fallback for this course"
    (e.g. `None`); otherwise, build a dict of submission records filtered to the requested
    `user_id`(s), each augmented with a nested `"assignment"` dict built from the matching
    assignment record's `id`/`name`/`due_at`/`points_possible`/`description` fields — matching
    exactly the shape `_info_blocks`/the "work" section loop already expect from `s.get(...)`
    and `s.get("assignment", {}).get(...)`.
  - A function resolving one comment's display label given `author_id`, `author_role`,
    `report_user_id`, `report_student_name` — implementing the locked comment-display rule
    above. Reuse `home_attention._author_role`/`_PROVEN_STAFF_ROLES` directly (import) rather
    than duplicating the role vocabulary, unless that import direction proves awkward (e.g. a
    circular import), in which case duplicate the frozen set with a comment noting it must stay
    identical to `home_attention.py`'s.
- **`build_packet` integration** (`api/student_packet.py:139-253`): inside the existing
  `for c in courses:` loop (~line 157), attempt the local assembly first; on the "use live
  fallback" sentinel, run exactly today's existing `_get_all_pages` call and downstream logic
  unchanged for that course. On a successful local assembly, skip the whole-course live fetch
  entirely for that course, and only call the new `fetch_submission` per `online_upload`
  submission when the "work" section is being written and `_download_binary` is about to run
  for attachments — construct the `requests.Session()` lazily (not unconditionally at line 143)
  so a fully-local run across all requested courses never touches `requests` at all. Every
  downstream call (`_info_blocks`, `_signature`, the "work" section's file-writing loop,
  `_manifest.json` read/write) operates on the assembled `subs` list exactly as it does today,
  regardless of which path produced it.
