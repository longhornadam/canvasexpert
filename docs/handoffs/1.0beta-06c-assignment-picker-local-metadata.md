# Serve the report/download assignment picker from Course Catalog

Status: **READY**

Risk: **low** - single read-only GET route; no writes, no Canvas mutation, existing live fetch
preserved as the fallback path.

Depends on: source HEAD `8eead15` (1.0beta-06b specced; independent of it — different files)

## Teacher-visible result

Opening the assignment picker on `/students/reports` (which lists every assignment so a
teacher can pick one to download/report on) makes **zero Canvas calls** when the course's
Course Catalog is current — it reads the exact same catalog data Course Info/Create's module
picker already trust. When the catalog isn't current, the picker falls back to exactly today's
live paginated fetch, unchanged.

## Background (read before writing code)

1.0beta-06a's non-goals deferred this exact migration, noting only that it "needs its own
dedicated investigation" before committing to it — that investigation is now done, in this
brief. `api/webui/routes/reports.py::list_assignments_full` (`GET /api/assignments-full`)
today does a raw, manually-paginated `requests.get` loop against
`{base}/api/v1/courses/{course_id}/assignments` (lines 33-56), then locally computes
`is_quiz`/`quiz_kind` (its own `_is_quiz`/`_quiz_kind` closures, lines 71-98) and an
`assignment_group_name` lookup from inline Canvas response data (lines 57-69), returning:
`id, name, submission_types, due_at (10-char date), points_possible, quiz_id,
assignment_group_id, assignment_group_name, is_quiz, quiz_kind, is_quiz_lti_assignment`,
sorted by `due_at` descending (lines 100-121).

Course Catalog's `normalize_assignment` (`api/course_catalog.py:340-365`) **already stores every
one of those fields** except the resolved group name: `id, name, points_possible, due_at (full
ISO string — a `[:10]` slice still yields the same date), submission_types, assignment_group_id,
quiz_id, is_quiz, quiz_kind, is_quiz_lti_assignment`, using its own `_quiz_classification`
helper (`api/course_catalog.py:322-337`) — the same detection logic
`list_assignments_full`'s `_is_quiz`/`_quiz_kind` reimplement independently today. The group
name is resolvable via `normalize_assignment_group` (`api/course_catalog.py:518-530`, has
`id`/`name`), exposed by `read_service.catalog_assignment_groups`. No Catalog schema change is
needed — this is a pure read-and-reshape migration.

## Acceptance criteria

- [ ] `list_assignments_full` reads `read_service.catalog_assignments(course_id)` and
  `read_service.catalog_assignment_groups(course_id)` first. When **both** envelopes report
  `state == "current"`, the response is built entirely from those records — zero Canvas calls
  — joining each assignment's `assignment_group_id` to its group's `name` (empty string when
  unmatched, matching today's `group_names.get(..., "")` fallback).
- [ ] The catalog-sourced response is field-for-field identical in shape to today's live
  response: same keys, same `due_at` truncated to 10 characters, same sort (`due_at` descending,
  missing due dates last, matching today's `"0000-00-00"` sentinel), same `is_quiz`/`quiz_kind`
  semantics (reusing Catalog's own `is_quiz`/`quiz_kind` fields directly — do not re-derive
  them with a second classification function).
- [ ] When either catalog envelope is not `"current"`, the route runs exactly today's existing
  live-fetch code (raw pagination, local `_is_quiz`/`_quiz_kind`, inline group-name lookup),
  unchanged — proven by a test that the live path's output is byte-for-byte what it is today.
- [ ] No route signature, response envelope (`{"ok": ..., ...}` vs. a bare list — confirm
  exact current response shape in preflight and preserve it), or error-handling behavior
  changes for either path.
- [ ] The named acceptance gate passes.

The executor reports evidence; the senior accepts only when every criterion holds.

  in flight against those files.

  this route) — the response shape is locked identical, so no frontend change is needed; verify
  this rather than assume it.
- Do not widen this migration to any other route in `reports.py`.

## Locked decisions

  re-run `list_assignments_full`'s local `_is_quiz`/`_quiz_kind` closures against catalog data;
  those closures remain only for the live-fallback branch, unchanged.
