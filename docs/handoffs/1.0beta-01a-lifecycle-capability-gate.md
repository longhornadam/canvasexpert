## Teacher-visible result

known-forbidden New Quiz calls. Concluded/retired courses show their New Quiz scope as
"restricted" instead of silently failing every 15 minutes. Current courses (e.g., the

## Background (established truth)

New Quiz endpoints are gated on **active enrollment** (`api/README.md` ~205-213): the same
token returns 200 in an actively-enrolled course and 403 in a concluded/past-enrollment
course. This is confirmed in production use. Today `sync_metadata`
(`api/mirror/new_quizzes.py:674-728`) fans out one GET per New Quiz per pass
(`/api/quiz/v1/courses/{c}/quizzes/{a}`, line 696); `_metadata_is_current` (line 660)
skips only previously-successful quizzes, so a 403-ing quiz retries every heartbeat
(`api/webui/mirror_service.py`, `TICK_SECONDS = 900`). No lifecycle or capability signal
is stored anywhere; `run_heartbeat_pass` iterates `config.active_courses()` — a pure
config-membership list. Design: **lifecycle predicts, probe confirms, circuit backstops**
(vision doc §9.4).

## Locked design for this slice

### 1. Per-course New Quiz capability record (student-free)

Persist a small capability envelope for the New Quiz metadata scope per course, stored
with the existing course sync-envelope machinery in `api/mirror/store.py` (same atomic
write and last-good rules). Allowed fields only:

- `capability`: `"supported" | "restricted" | "unknown"` (`"unsupported"` reserved, unused
  for now);
- `last_probe_at`, `retry_after`: ISO-8601;
- `evidence`: stable sanitized category (`"forbidden"`, `"unauthorized"`) plus consecutive
  failure count.

Forbidden at rest: status text, response bodies, URLs, quiz titles, any student data.

### 2. Classification rule (locked — do not re-derive)

The enrollment gate makes New Quiz 403s course-level. Rule: **3 consecutive distinct-quiz
`HTTP 403`/`HTTP 401` failures with zero successes in the same `sync_metadata` run →
`capability = "restricted"`, `retry_after = now + 24h`.** Any single success in a run
resets the scope to `supported` and clears the cooldown. Mixed runs (some 200, some 403)
remain `supported` — those failures are item-level noise and keep today's behavior.
Classify by parsing the `HTTP 403`/`HTTP 401` prefix of the existing error string; do not
rewrite `canvas_client` error handling in this slice.

### 3. Gate in `sync_metadata`

At entry: if the stored capability is `restricted` and `now < retry_after`, skip the
entire fan-out and record the scope as skipped-restricted. When `retry_after` passes, the
next run performs **one bounded probe** (the first quiz in the list); a 403/401 renews the
cooldown without touching the remaining quizzes; a success clears it and proceeds
normally.

### 4. Manual override

`sync_now(course_id)` (explicit manual sync) ignores the cooldown and performs a full
probe — the manual-diagnostic override from vision §9.3. The 15-minute heartbeat never
ignores it.

### 5. Sanitized visibility

Count skipped-restricted runs and circuit opens/clears in whatever sanitized sync summary
`_record_sync`/heartbeat already produce, so 01a's effect is observable. Course alias or
synthetic ID only; no course names.

Out of locked scope but explicitly noted for the senior: probing
`GET /api/quiz/v1/courses/:id/quizzes` (collection) as a one-call probe/bulk source is a
Program 0 investigation; this slice keeps the per-quiz endpoint.

## Execution result

**GREEN.**

Preflight confirmed all four expected facts (per-quiz sequential GETs with no
failure gate; `canvas_client` errors collapse to `HTTP {status}: ...`; no
existing capability/cooldown/retry_after machinery). Implemented the locked
design exactly:

1. **Capability envelope** — new `new_quiz_capability.v1.json` per course in
   `api/mirror/store.py` (`read_new_quiz_capability` / `write_new_quiz_capability`
   / `validate_new_quiz_capability`), using the same `course_dir` /
   `course_lock` / `atomic_write_json` conventions as the rest of the module,
   but as its **own file** rather than widening `_sync.v1.json`'s exact-key
   schema — this sidesteps the RED condition about bumping the course
   sync-envelope schema version. Fields: `capability`
   (`supported`/`restricted`/`unknown`), `last_probe_at`, `retry_after`,
   `evidence` (`category`: `""`/`forbidden`/`unauthorized`,
   `consecutive_failures`). Exact-key validation rejects anything else.
2. **Classification** — `api/mirror/new_quizzes.py`: `_classify_http_error`
   parses the existing `HTTP 403`/`HTTP 401` string prefix (no
   `canvas_client` changes). 3 consecutive distinct-quiz classified failures
   with zero successes in one `sync_metadata` run opens the circuit
   (`retry_after` = now + 24h); any success clears it; mixed runs stay
   supported.
3. **Gate** — `sync_metadata` skips the entire fan-out (zero Canvas calls)
   while restricted and within cooldown. Once the cooldown passes, it makes
   exactly one bounded probe (first quiz); a classified failure renews the
   cooldown without touching the rest; a success clears the restriction and
   the remaining quizzes are processed normally in the same run.
4. **Manual override** — `sync_metadata(..., bypass_cooldown=True)`;
   `mirror_service.sync_now` always passes `bypass_cooldown=True` through
   `sync.delta_pass`/`full_pass` (new `bypass_new_quiz_cooldown` kwarg,
   default `False`); the heartbeat (`run_heartbeat_pass`) never passes it.
5. **Sanitized visibility** — `sync_metadata`'s return dict gained
   `capability`, `skipped_restricted`, `circuit_opened`, `circuit_cleared`
   (booleans/enum only — course_id was already the only course identifier in
   these summaries, never a name).

Also updated `docs/mirror.md` (on-disk layout + a new "New Quiz capability
gate" section) so the current-behavior doc stays accurate.

**Deviation (small, necessary):** `api/mirror/sync.py`'s `full_pass`/
`delta_pass` gained a `bypass_new_quiz_cooldown: bool = False` passthrough
kwarg. Not in the brief's listed Scope, but unavoidable — `sync_metadata` is
only ever invoked from inside these two functions, so the manual-override
flag from `mirror_service.sync_now` has nowhere else to travel through.
Backward compatible (default `False`; heartbeat call sites unchanged).

**Deviation (test-shape):** the pre-existing exact-dict-equality assertion in
`test_metadata_sync_skips_unchanged_quizzes_until_trueup`
(`api/tests/test_mirror_new_quizzes.py`) was updated to include the four new
return keys — required since the brief's own point 5 mandates widening this
return shape.
