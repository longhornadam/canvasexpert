## Locked design for this slice

### 1. One compute owner: the adapter's `_compute_sweep`

Fix `_compute_sweep` semantics:

- `school_days, excluded = _school_days_late_detail(...)` stays; **delete the
  `if excluded: skip` branch** — the count already excludes those days.
- Each entry gains `canvas_days` (raw calendar days late: `(subd.date() -
  due.date()).days`) and `excluded_dates` (the list) for the UI columns. `skipped` is
  reserved for genuinely unsweepable rows (excused/unsubmitted/unpublished — the
  existing `continue`s).
- Honor `date_from`/`date_to` from settings: skip assignments whose `due_at` falls
  outside the inclusive range when either bound is provided.
- `honor_extra_time`: implement ONLY if it reduces to adjusting the effective due date
  with an existing helper (`_add_school_days` + the roster extra-time settings, or an
  existing gradebook_service helper). If it requires new modeling, REMOVE the
  `sw-extra` checkbox from the UI instead (a control that does nothing is deceptive)
  and record the removal for a future brief. Do not invent new extra-time semantics.

### 2. Preview delegates; the broken compute dies

- `/api/sweep/preview` calls the adapter's `_compute_sweep` and returns
  `{ok, entries, skipped}` in a shape `sweep.js` renders (update JS/columns minimally
  if field names shift).
- Delete `gradebook_service._sweep_compute` and its re-exports
  (`routes/gradebook.py` facade, `server.py` if present). Update
  `test_mirror_reads_helper.py`'s liveness lock to target the adapter's
  `_compute_sweep` — the locked *decision* (sweep compute stays fully live, never
  mirror-fed) is unchanged; only the symbol moves.

### 3. Write-boundary rules unchanged

No change to prepare/review/apply flow, drift, idempotency, receipts, or the
`seconds_override = school_days * 86400` formula. Baseline/drift/freeze continue to
work over the corrected entries. The three healthy consumers are untouched.

**Commit:** (this commit, on `dev`)

**RED-condition analysis (why implementation proceeded):** deleting the
`if excluded: skip` branch only ADDS previously-dropped rows — every row the old
adapter compute DID include had an empty `excluded` list, so its
`school_days`/`seconds_override` are computed identically before and after. The two
behaviors that can change values for previously-included rows — the date-range filter
and extra-time subtraction — are explicitly ordered by locked design item 1, and the
extra-time semantics (`max(school_days - extra_days, 0)`, skip at 0) mirror the routine
sweep/late-catchup/late-work consumers exactly.

**honor_extra_time decision:** implemented (no YELLOW fallback needed) — it reduces to
`config.get_extra_time(course_id)` + per-student day subtraction, the identical pattern
`routines_builtin._run_routine_sweep` already uses. The `sw-extra` checkbox stays and
now actually works.
