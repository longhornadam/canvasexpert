# Migrate merged writing portfolios to local metadata + focused evidence

Status: **READY**

Risk: **medium** - read-only migration of a teacher-initiated, non-Canvas-mutating report
generator; the existing live fetch is preserved as the fallback path, not deleted.

Depends on: source HEAD `481ed5f` (1.0beta-06a GREEN and archived)

## Teacher-visible result

Building merged writing portfolios for a cohort (`/api/portfolio/merged`) against a
local-current course makes **one** local read for the whole cohort instead of today's one live
paginated Canvas fetch **per student** — the single biggest efficiency win available in Batch
5's remaining scope, since `build_merged_portfolios` currently re-fetches the same course's
submissions once per selected student even though every student's data comes from the same
course. Attachment files still require a live fetch, but only for the one submission that
actually has a file, not a whole-course or whole-student fetch. When the course's mirror isn't
current, every student falls back to exactly today's existing per-student live fetch, unchanged
— nothing that works today stops working. No New Quiz CSV-merge behavior, DOCX rendering, or
output path changes.

## Background (read before writing code)

`docs/handoffs/archive/1.0beta-06a-student-reports-local-metadata.md` (GREEN, commit `e595c47`)
built the first consumer of this pattern for `api/student_packet.py::build_packet` (a
single-student, multi-course packet) and established two reusable pieces this brief extends
rather than re-derives:

- `api/report_local_reads.py::local_course_submissions(course_id, user_id, *, root=None)` —
  joins one course's local assignments+submissions for **one** student, returning `None` when
  either envelope isn't `state == "current"` (meaning: use the live fallback for this course).
- `api/submission_transport.py::fetch_submission(session, base, course_id, assignment_id,
  user_id)` — one focused live fetch of a single submission's current `attachments`, returning
  `None` on any failure.

`api/portfolio_service.py::build_merged_portfolios` is single-course, multi-student (the
inverse shape of `build_packet`): it takes one `course` and a `students` list, and today calls
`_get_all_pages` with `student_ids[]=<uid>` **inside its per-student loop** — meaning a 30-student
cohort makes 30 separate live paginated submission fetches for the exact same course. Since
mirror currency is a course-level property, not a per-student one, this brief can read the
whole course's local data **once** and slice it per student in memory.

`_assignment_entries` (the function that shapes a student's submissions into portfolio
entries) does not use `submission_comments` at all — this brief has no comment-display
question to resolve; 06a's role-label rule is out of scope here entirely.

## Acceptance criteria

- [ ] A new `api/report_local_reads.py::local_course_submissions_by_user(course_id, *,
  root=None) -> dict[str, list[dict]] | None` returns `None` under the exact same
  not-current gate as `local_course_submissions`, else a dict keyed by `user_id` (string) of
  every student's joined records for the course, in the identical per-record nested shape
  (`s["assignment"]["name"]`, etc.). Both functions share one underlying join pass — no
  duplicated read/join logic between them.
- [ ] `local_course_submissions`'s existing public signature, return shape, and behavior for
  `build_packet` are byte-for-byte unchanged — this is a refactor to share logic, not a
  behavior change, proven by `build_packet`'s existing 1.0beta-06a test suite still passing
  unmodified.
- [ ] `build_merged_portfolios` calls `local_course_submissions_by_user` **once**, before the
  per-student loop, not per student. When it returns a dict (course is local-current), every
  student in that run is sliced from the same in-memory result — zero additional local reads,
  zero Canvas calls, per student.
- [ ] When `local_course_submissions_by_user` returns `None` (course not local-current), every
  student falls back to exactly today's existing per-student `_get_all_pages` fetch and
  `except Exception` handling, unchanged.
- [ ] For a local-current course, a live focused call via `fetch_submission` happens only for
  a given student's submissions whose `submission_type == "online_upload"` — never for
  `online_text_entry`/`online_quiz`, and never for a student whose local record set is empty.
  A `requests.Session()` is constructed lazily, only the first time such a call (or the
  not-current live fallback) is actually needed for a given `build_merged_portfolios` run.
- [ ] A cohort run against a fully local-current course with no `online_upload` submissions
  anywhere in the selected students' records makes **zero** Canvas calls total — proven by a
  test asserting no Canvas-calling function is invoked for the whole run, not just per-student.
- [ ] `_assignment_entries`, `portfolio.render_merged_docx`, `portfolio.nq_entries`, the
  `date_from`/`date_to` filtering, the `nq_map` CSV-merge logic, and the temp-dir
  download/cleanup lifecycle are unedited — only `build_merged_portfolios`'s fetch integration
  changes. `_assignment_entries` already accepts a `session` and reads `s.get("attachments")`
  generically; it needs no changes as long as `attachments` is populated correctly before it
  runs, by either the live path (unchanged) or the new focused-fetch step (new).
- [ ] The named acceptance gate passes.

The executor reports evidence; the senior accepts only when every criterion holds.

## Locked decisions

- Refactor `api/report_local_reads.py`: extract a private `_joined_course_records(course_id, *,
  root=None) -> list[dict] | None` performing the exact current read+join logic
  `local_course_submissions` already has (~lines 25-60), minus the per-user filter. Have
  `local_course_submissions(course_id, user_id, *, root=None)` call it and filter to
  `user_id` (preserving its exact existing public behavior/return shape for `build_packet`).
  Add `local_course_submissions_by_user(course_id, *, root=None) -> dict[str, list[dict]] |
  None` that calls the same helper and groups by `str(sub.get("user_id"))` instead of
  filtering to one. Both public functions return `None` under the identical not-current gate.
- In `api/portfolio_service.py::build_merged_portfolios`, call
  `report_local_reads.local_course_submissions_by_user(cid)` once, immediately after `cid =
  str(course["id"])`, before the `for stu in students:` loop. Store the result; `used_local =
  <result> is not None`.
- Inside the per-student loop: if `used_local`, `subs = <result>.get(uid, [])`; else, run
  exactly today's existing `_get_all_pages(...)` call and `except Exception` handling for that
  one student, unchanged.
- Session laziness: replace the unconditional `session = requests.Session()` /
  `session.headers["Authorization"] = ...` at the top of `build_merged_portfolios` with the
  same lazy `_session()` closure pattern 1.0beta-06a introduced in `student_packet.py` (a
  `session_box`/closure, not a module-level helper — keep each function's own lazy session
  independent, matching the existing precedent rather than introducing shared session state
  across modules).
- For each `used_local` student's `subs`, before calling `_assignment_entries`, iterate and for
  every record with `submission_type == "online_upload"`, call `fetch_submission(_session(),
  base, cid, record.get("assignment_id"), uid)`; on a non-`None` result, set
  `record["attachments"] = fetched.get("attachments") or []`. This mirrors 06a's exact
  `student_packet.py` pattern — reuse that shape, don't invent a new one.
- `_assignment_entries`'s call signature and body are unchanged; pass it `_session()` (lazily
  resolved) in place of today's unconditional `session` wherever it's called, for both the
  local and live-fallback branches (the live branch already has real attachments from Canvas
  and doesn't need the focused fetch, but still needs a session for `_download_binary`).
