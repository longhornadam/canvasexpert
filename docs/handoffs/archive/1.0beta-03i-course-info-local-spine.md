# Serve Course Info from the local read spine

Status: **READY**

Risk: **medium** - migrates Course Info display reads from live Canvas to existing private
roster/group and student-free catalog projections, and removes a PII column; no new
persistence, no write/preflight path, no schema change.

Depends on: current `dev` after `c433410` (03f roster-groups snapshot, 03g cadence, 03h
snapshot consumers, and the roster mirror read already landed).

## Teacher-visible result

Opening Course Info renders assignments, students, and group sets from last-good local state
with no Canvas calls when those scopes are usable, instead of re-fetching the whole roster,
every group's memberships (N+1), and the assignment collection live on every load. Assignment
names stay clickable. The student **email column is removed** (locked senior decision).
Modules remain a live read this batch. Any non-current/missing scope silently falls back to
its existing live call.

## Acceptance criteria

- [ ] `GET /api/course-detail` serves the **assignments** list from the Course Catalog when
  the catalog exists and its `assignments` scope is exactly `current`; each item keeps the
  existing six display fields (`id`, `name`, date-only `due_at`, `points`, `published`,
  `html_url`) where `html_url` is **reconstructed at read time** as
  `f"{base}/courses/{course_id}/assignments/{id}"` from `_canvas_headers()` and the catalog
  `id` — never read from a persisted field. No catalog envelope/source/freshness fields leak.
- [ ] It serves **students** (name, sortable_name) from `roster.v1.json` when its state is
  `current`; the `email` field is removed from the response entirely.
- [ ] It serves **group sets** from the `groups.v1.json` snapshot when
  `groups_are_current(..., max_age_hours=24)`, mapping member IDs to names using the roster
  mirror's students (preserving the existing `{name, groups:[{name, members:[names]}]}`
  shape). No per-membership live fan-out on the current-snapshot path.
- [ ] Each scope independently falls back to its existing live call when its projection is
  missing, stale, incomplete, unavailable, or malformed. Existing error/empty behavior holds.
- [ ] `course_info.js` no longer renders the email cell (header + row), and no longer expects
  `email` in the payload; the assignment-name link behavior is unchanged.
- [ ] Modules read stays live and unchanged. No write, preflight, or reconciliation path is
  touched. No new field is persisted anywhere; no catalog/roster/groups schema changes.
- [ ] The named acceptance gate below passes.

The executor reports evidence; it does not redefine, narrow, or self-accept these criteria.

## Locked decisions

- **html_url** is a transiently-computed display value, precedented by `public_projection`'s
  derived-but-not-persisted `assignment_ids`/`quiz_ids` (catalog contract line ~100). The
  contract's forbidden-material rule governs what is **persisted**, not what a route computes.
- **Email column removed** (privacy-lean; roster mirror deliberately excludes email at rest).
- Local facts are display-only and never authorize a mutation or placement decision.
- Per-scope current-vs-fallback is independent: one stale scope must not force the others live.

### Changed files

- `api/webui/routes/courses.py` — `course_detail` now source-selects assignments (via
  `api.course_catalog.read_catalog`), students (`mirror_store.read_roster`), and group sets
  (`mirror_store.read_groups` + `groups_are_current` + `groups_for_roster`), each with an
  independent local/live decision; three new private helpers
  (`_local_students`, `_local_group_sets`, `_local_assignments`) return `None` to signal
  "use the existing live call." The live group-fallback path and the live-students fallback
  path now reuse one shared `name_by_id` (built from whichever source — local mirror or one
  live `/users` call — actually produced the roster display), so the fully-live legacy
  scenario still makes exactly one `/users` call, matching prior behavior. `email` removed
  from the `include[]` param and from the response. Modules block untouched.
- `api/webui/static/course_info.js` — `renderRoster` no longer builds an email `<td>`; empty
  state colspan corrected from 2 to 1. `renderAssignments`/link behavior untouched.
- `api/webui/templates/course.html` — **undeclared-file deviation**: removed the static
  `<th>Email</th>` header cell from the roster `<thead>`. This file was not listed in Scope
  or References, but the acceptance criterion "`course_info.js` no longer renders the email
  cell (**header** + row)" cannot be satisfied by editing `course_info.js` alone — the header
  row is static Jinja markup, not JS-rendered; the JS only ever built `<tbody>` rows. Leaving
  it in place would render a 2-column header over a 1-column body (visibly broken). The edit
  is a one-line, mechanical removal with no behavior/architecture implication.
- `api/tests/test_course_info_routes.py` — new file, 11 tests covering the named gate's five
  bullets (current-catalog/roster/groups paths, per-scope independent fallback in both
  directions for all three scopes, malformed-projection fallback for all three scopes, the
  full-live-fallback shape parity check including the single-`/users`-call assertion, and a
  no-leak check for email/token/"signed").
- `docs/mirror.md` — added one line stating Course Info's local-spine read boundary
  (assignments/students/group sets read local-when-current with independent live fallback;
  email removed; modules stay live).
