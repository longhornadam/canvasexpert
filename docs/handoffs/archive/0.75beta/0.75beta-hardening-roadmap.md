## Outcome

Before first school-year use, CanvasExpert has:

- transaction-safe private JSON stores for the web process, routines thread, and
  separate MCP process;
- one enforced external-AI send boundary and a PII-minimized operational log;
- a versioned MCP schema and application services shared by HTTP and MCP adapters;
- a sanitized diagnostics bundle and an honest Connections page;
- one package import model and no unused legacy activity/FeedbackExpert surfaces;
- a deliberately small regression net during implementation, followed by one full
  API-suite and rendered-browser acceptance pass at the end.

This remains a local, pre-deployment hardening program. There are no live users and
no schedule emergency. Prefer correctness and debuggability over compatibility with
dead code.

## Locked program decisions

These decisions are already made. An executor must not revisit them.

1. Python, JSON storage, plain browser JavaScript, the single-ZIP/no-admin model,
   keyring-only Canvas PAT storage, and the `127.0.0.1` web bind remain unchanged.
   A teacher unzips one CanvasExpert folder and runs it in place; this refactor may not
   introduce an installer or elevation step.
2. `engine/` is out of scope. MCP stays read-only. No generic Canvas endpoint tool,
   repository framework, ORM, DI container, frontend build system, or public route.
3. Every external-AI payload is pseudonymized and scanned immediately before the
   provider call. A caller cannot bypass the boundary by calling
   `openrouter_client.score()` directly.
4. Operational logs are safe by construction: a small allowlisted schema, no
   payloads, names, IDs, URLs, paths, provider bodies, comments, or arbitrary detail.
5. The three unregistered route modules `feedback_run.py`, `feedback_manual.py`, and
   `feedback_push.py` are deleted. `_push_payload` has no production consumer; delete
   it and its isolated test instead of moving dead code. `feedback_pipeline.py` and
   the active feedback library router stay.
6. `_upsert_roster` becomes mutation-only. Persistence is owned by the caller's vault
   transaction; there is never a hidden or duplicate save.
7. Workspace-derived paths are functions evaluated at call time. No workspace path,
   AI-TA directory, rubric folder list, or content folder list may be captured at
   module import.
8. MCP tool names and required inputs are a public versioned contract backed by a
   checked-in schema snapshot. Schema version 1 has exactly five read-only tools.
9. The Claude package is current `.mcpb`, not legacy `.dxt`. CanvasExpert generates a
   small launcher package that points back at the teacher's unzipped CanvasExpert folder;
   it does not install, fork, or copy the MCP implementation.
10. ChatGPT cannot connect directly to local stdio. Its card documents the optional
    outbound Secure MCP Tunnel flow. CanvasExpert does not download/install/start the
    tunnel, store its runtime API key, or claim that workspace/platform permissions are
    configured. Absence of that external optional client never blocks CanvasExpert or MCP.
11. V1 writes no Claude, ChatGPT, or generic-client configuration file. It offers an
    `.mcpb` download and copyable resolved snippets, so existing client servers cannot
    be overwritten.
12. The legacy `/api/activity` feed is unused by browser code and is removed. It is
    not renamed or merged into the sanitized support log.
13. Optional global CSRF middleware is deferred. Existing guarded operation/work
    routes stay guarded; expanding that to every form POST is a separate behavior
    change. Vault-at-rest encryption also remains deferred.
14. Do not add a WebView2 probe. Canvas Expert launches the installed system browser and
    has no embedded WebView2 runtime seam. Diagnostics cover the actual Python, Canvas
    configuration, workspace, MCP, proxy, and tunnel-client dependencies instead.

## Portable/no-elevation contract

These rules apply to every slice, especially slices 1, 4, 5, 6, and 7:

1. CanvasExpert and its MCP server run from the single folder the teacher unzipped. Moving
   that folder is supported after regenerating any path-bearing connection snippet/package.
2. Reuse the exact Python executable and dependencies already running CanvasExpert. MCP
   may not call `pip`, `npm`, `mcpb`, `winget`, `choco`, an MSI/EXE installer, or any other
   dependency/bootstrap installer.
3. Never request elevation or use `runas`, UAC prompts, `ShellExecute` elevation, a Windows
   service, scheduled task, firewall rule, registry write, machine/user PATH change, or
   writes under `%ProgramFiles%`/`%WINDIR%`.
4. CanvasExpert writes no client configuration and copies no application files outside its
   unzipped folder. Normal user-owned runtime state already required by the product remains
   allowed: credential-store secrets, selected workspace data, `%LOCALAPPDATA%` logs, and
   temporary downloads.
5. Claude's **Install Extension** label is a user-level import performed by an already
   installed Claude Desktop client. It must not invoke a Windows installer or require admin
   rights. The generated package links back to the unzipped folder.
6. ChatGPT tunnel setup is optional external client infrastructure. If a teacher/district
   supplies a portable `tunnel-client.exe`, it may be placed under the same unzipped folder's
   `tools/` directory and invoked directly. CanvasExpert itself must work fully without it.

## Program stop conditions

Return RED rather than inventing a solution when:

- a named production symbol or route does not exist and the difference is not a
  simple move already explained in the current slice;
- preserving correctness requires a new persistence format, public contract, Canvas
  write path, credential store, network listener, or external-AI payload;
- a private store cannot be made transactional without changing its durable JSON
  shape;
- an MCP projection cannot pass the existing feedback safety gate;
- a support artifact would need raw settings, a vault, course data, receipts, paths,
  environment values, provider bodies, or free-form exception text;
- any MCP/Connections behavior requires an installer, elevation, machine-wide setting,
  service, registry/PATH/firewall change, or copying CanvasExpert out of its unzipped folder;
- a high-risk behavior is not covered by one of the locked 12 sentinels;
- cumulative sentinel count exceeds 12 before slice 7.
