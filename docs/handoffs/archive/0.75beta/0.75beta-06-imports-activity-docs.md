Then run this AST inventory. It prints every production or test import that loads an
`api/`-owned root module under a flat name; it is more reliable than maintaining a
handwritten regex list:

```powershell
@'
import ast
from pathlib import Path
root = Path("api")
owned = {p.stem for p in root.glob("*.py")} | {
    p.parent.name for p in root.glob("*/__init__.py")
}
for path in root.rglob("*.py"):
    tree = ast.parse(path.read_text(encoding="utf-8-sig"))
    hits = set()
    for node in ast.walk(tree):
        if isinstance(node, ast.Import):
            hits.update(a.name.split(".")[0] for a in node.names
                        if a.name.split(".")[0] in owned)
        elif isinstance(node, ast.ImportFrom) and node.level == 0 and node.module:
            top = node.module.split(".")[0]
            if top in owned:
                hits.add(top)
    if hits:
        print(f"{path}: {', '.join(sorted(hits))}")
'@ | py -
```

## Locked import rule

Application code has one canonical package identity:

- Cross-package imports use `api.<package>...`.
- Imports inside one package may be explicit relative imports or full `api.*` imports.
- “Application-owned” means any module file directly under `api/` or package directory
  directly under `api/`; derive that set exactly as the AST inventory does instead of
  maintaining a partial allow/deny list.
- Tracked tests also import application modules through `api.*`; update any flat test
  import mechanically. Test-only path setup may remain when a subprocess fixture needs it,
  but it may not be used to create a second module identity.
- Do not preserve `try: from api... except ModuleNotFoundError: from flat_module...`
  compatibility branches.
- Do not load the same file under both `api.foo` and `foo` names.
- `sys.path` bootstrapping is allowed only in true direct-process entrypoints that cannot
  import `api` until the repository root is known. Each entrypoint resolves the repo root
  from `__file__`, inserts it at most once, and performs no other path mutation.
- Library modules, routes, services, `api/mcp_server/server.py`, and
  `api/webui/routes/push_validation.py` may not mutate `sys.path`.
- Preserve every documented direct CLI and `py -m ...` form. Do not remove CLI support to
  make the import scan pass.
- Entry-point bootstraps only make the unzipped folder importable. They may not install a
  package, invoke `pip`, modify PATH/registry, copy the app elsewhere, or request elevation.

Expected entrypoint treatment:

1. `api/qf_ui.py`: a tiny repository-root bootstrap before importing `api.webui.server`;
   preserve the `127.0.0.1` bind and current port behavior.
2. `api/mcp_server/__main__.py`: preserve both direct-file and module execution, but insert
   only the repository root and only when it is absent.
3. `api/qf_pusher.py`, `api/push_tiers.py`, `api/validate_qf.py`, and
   `api/diagnose_newquizzes.py`: preserve their documented direct-script forms; normalize
   imports without changing arguments or side effects.
4. `api/mcp_server/server.py`: import `api.student_packet` canonically and retain the
   public `run_stdio()` seam created in slice 4 for slice 5's launcher.
5. `api/webui/routes/push_validation.py`: remove its library-time path edit and use
   canonical imports.

Do not create a generic import registry, alias entries in `sys.modules`, a new build
system/installer, or a repository-wide relative-import rewrite.
