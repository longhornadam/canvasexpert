## Locked schema contract

Create `api/mcp_server/tool_schema_v1.json` containing only stable interface facts:

```json
{
  "schema_version": 1,
  "tools": [
    {"name": "list_courses", "required": [], "properties": {}},
    {"name": "get_course_assignments", "required": ["course_id"],
     "properties": {"course_id": "string"}},
    {"name": "get_roster", "required": ["course_id"],
     "properties": {"course_id": "string"}},
    {"name": "get_submissions", "required": ["course_id", "assignment_id"],
     "properties": {"course_id": "string", "assignment_id": "string"}},
    {"name": "get_gradebook_snapshot", "required": ["course_id"],
     "properties": {"course_id": "string"}}
  ]
}
```

Sort tools and property keys deterministically when comparing; required-list order is
the Python signature order and is significant.

Create `api/mcp_server/contract.py` with:

```python
TOOL_SCHEMA_VERSION = 1
load_contract(version: int = TOOL_SCHEMA_VERSION) -> dict
live_contract(mcp) -> dict
```

`live_contract` normalizes FastMCP's registered tool JSON schemas into exactly the
shape above. Use the current `_tool_manager`; the CanvasExpert runtime's FastMCP version
already exposes it and the existing test uses it. Keep that private-library
access isolated in `contract.py`.

The rule for future changes is explicit: changing a name, removing a property, adding
a required property, or changing a property type requires a new immutable
`tool_schema_vN.json` and a `TOOL_SCHEMA_VERSION` bump. Adding an optional property is
also captured but may remain backward compatible; it still requires a versioned
snapshot update. Slice 5 displays the integer version in diagnostics.

Do not add a schema-version MCP tool; the public tool count stays five.

Expose one transport runner from `api/mcp_server/server.py`:

```python
def run_stdio() -> None:
    mcp.run(transport="stdio")
```

Update `api/mcp_server/__main__.py` to call `run_stdio()` rather than reaching into the
`mcp` object. Do not normalize its bootstrap/import model yet; slice 6 owns that mechanical
change. Slice 5's Claude launcher and the normal module entrypoint will then share one
public start seam.

### Portable MCP launch constraint

The server is part of the unzipped CanvasExpert folder, not a separately installed app.
It must run with the exact interpreter returned by `runtime_paths.python_executable()` and
the absolute script returned by `runtime_paths.mcp_entrypoint()`, regardless of the
client's working directory. Import/start may not:

- install or update Python/MCP packages;
- look up a globally installed CanvasExpert module;
- alter PATH, registry, firewall, services, or scheduled tasks;
- write outside the existing CanvasExpert runtime-state locations;
- request elevation or bind a network listener.

A missing dependency is an honest health/error state. It is never repaired from inside the
MCP process. The normal CanvasExpert launcher/distribution remains the sole owner of making
the base application runnable.
