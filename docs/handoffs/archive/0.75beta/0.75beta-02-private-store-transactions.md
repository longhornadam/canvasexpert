## Locked storage primitive

Create `api/storage_support.py` and move—not copy—the proven neutral primitives into
it:

```python
interprocess_lock(lock_path: Path)       # adjacent-byte OS lock, reentrant per thread
atomic_write_bytes(path: Path, payload: bytes)
atomic_write_json(path: Path, document: dict)
```

Preserve same-directory temporary files, flush, `os.fsync`, `os.replace`, cleanup on
failure, Windows `msvcrt.locking`, POSIX `fcntl.flock`, and the thread-local re-entry
guard. `atomic_write_json` accepts only a dict and writes UTF-8/indented/non-ASCII JSON.

Strengthen `interprocess_lock` at the neutral seam so it is also correct between threads
in one process: acquire a process-local `threading.RLock` keyed by the canonical lock path
before acquiring the OS byte lock. Protect the small lock registry with its own mutex.
Nested acquisition of the same path by the same thread must take the local `RLock` but
must not reacquire the OS byte. Release in reverse order. This is concrete lock plumbing,
not a generic repository abstraction.

`api/operation_ledger/storage.py` imports these functions from `api.storage_support`.
`api/operation_ledger/file_lock.py` is deleted after every importer moves. Do not alter
ledger validation, quarantine, transaction boundaries, or JSON schemas.

Every private store owns its own transaction. Do **not** add a generic repository or a
generic JSON mutation callback framework.

## Store-by-store transaction contract

### 1. Identity vault

Add `Vault.transaction()` as a context manager:

1. Acquire an adjacent lock derived from the actual vault path (for example
   `vault.json.lock`).
2. Reload the latest disk document into the same `Vault` instance while holding the
   lock. Reload must clear stale in-memory maps before applying disk state.
3. Yield that instance for all related mutations and projections.
4. On clean exit, atomically save once while still holding the lock.
5. On exception, do not save and re-raise.

Keep direct `Vault.save()` for compatibility tests and one-shot creation, but make it
atomic and lock-protected. Production read-modify-write paths must use
`transaction()`; a separate `load → mutate → save` sequence is forbidden.

Convert all production vault mutation call sites found by preflight. The minimum set
includes `routes/names.py`, `routes/roster.py`, `routes/roster_updates.py`,
`powergrader/ai_workflow.py`, `feedback_artifacts.py`, and MCP roster/submission/
gradebook flows. Build the final safety projection inside the transaction so a
pseudonym assigned during the operation is already durable when returned.

The transaction is about local processes. Do not add encryption or change vault keys.

### 2. Machine and workspace settings

In `config/_io.py`, add explicit locked mutation functions:

```python
_modify_machine(mutator) -> dict
_modify_workspace(mutator) -> dict | None
_modify_synced(mutator) -> dict
```

Each function acquires a lock adjacent to the authoritative file, reloads inside the
lock, calls a mutator on the latest dict, and atomically saves inside the same lock.
Return a copy/current document for callers that need it. The workspace function
returns `None` when no workspace exists.

Keep `_machine_load`, `_workspace_load`, and `_synced_state` as read APIs. Make
`_machine_save`, `_workspace_save`, and `_save_synced_key` atomic and locked for
compatibility, but do not use them for a multi-step production mutation.

Update setters that currently read a nested dict and later call `_save_synced_key` to
perform the entire mutation under `_modify_synced`. Audit all setters in:

- `canvas.py`, `courses.py`, `calendars.py`, `gradebook.py`
- `roster.py`, `reports.py`, `feedback.py`, `protected_names.py`, `routines.py`

Preserve every key, default, migration, workspace-authoritative merge rule, and
last-writer-wins behavior between different OneDrive machines. This slice protects
processes on one machine; it does not invent distributed locking.

Credential writes remain keyring calls and never enter these JSON transactions.

### 3. PowerGrader sessions

Upgrade `session_store.session_lock(session_id)` so it acquires both the existing
per-session `threading.RLock` and an interprocess lock adjacent to that session's
canonical JSON path. The thread lock is outermost; the file lock is innermost. Reentry
in one thread must remain safe.

Make `save_session` atomic. Then audit every production `load_session → mutate →
save_session` sequence. It must be wholly inside `session_lock`, including the
authoritative reload. Do not load before acquiring the lock. At minimum inspect:

- `api/powergrader/import_results.py`
- every public mutator in `api/powergrader/session_actions.py`
- `api/webui/routes/powergrader.py`
- `api/webui/routes/powergrader_late.py`
- `api/webui/routes/routines_powergrader.py`

Initial creation of a brand-new session may call atomic `save_session` directly only
when no document with that ID exists. If an existing ID could be replaced, use the
lock. Preserve the interactive auto-post rule that the lock spans authoritative
reload, fresh Canvas checks, write, receipt, and final save.

Do not add a new session wrapper class or change the session JSON schema.

### 4. Autoscore queue

Add `autoscore_queue.queue_transaction()`:

1. Acquire one process `RLock` and one adjacent interprocess lock.
2. Reload the current queue inside both locks.
3. Yield the queue dict.
4. Atomically save once on clean exit; do not save on exception.

Make `upsert_job` use this transaction. In
`routes/routines_powergrader.py`, place its existing queue load/mutation/final save
inside one queue transaction and remove the separate final `save_queue`. Holding this
small local lock during the current routine body is an accepted v0.75 tradeoff; do not
redesign job claiming or scheduled-write policy in this slice.

Read-only `load_queue` remains available and lock-protected. Direct production
`save_queue` calls outside `queue_transaction` are forbidden after this slice.
Preserve queue version, job fields, claims, statuses, idempotency, and auto-push policy.

### 5. Legacy activity log

Do not make `activity_log.json` transactional. Slice 6 removes it after the sanitized
operational log exists.

## The three sentinel tests

Create `api/tests/test_beta075_storage.py` with exactly three non-parametrized tests.
Top-level multiprocessing workers are required for Windows spawn portability.

1. `test_spawned_vault_writers_preserve_both_students`
   - Start two spawned processes against one temporary `vault.json`.
   - Synchronize them with a barrier so both contend for `Vault.transaction()`.
   - Each adds a different synthetic student and exits normally.
   - Assert both processes exit 0, the JSON parses, both IDs exist, pseudonyms differ,
     and a fresh Vault reverses both pseudonyms.

2. `test_settings_transactions_preserve_interleaved_nested_updates`
   - Redirect both machine config and workspace settings to `tmp_path`.
   - Use two threads/processes that wait at a barrier immediately before invoking public
     setters, then update different course or roster entries under the same nested synced
     key; also update two different machine keys. Never wait at a barrier from inside a
     locked mutator, which would deadlock the second worker.
   - Assert no nested entry or unrelated key is lost and both files remain valid JSON.
   - Loop once with no workspace and once with a workspace inside this single test;
     do not parametrize it.

3. `test_session_and_queue_transactions_preserve_interleaved_updates`
   - Redirect the workspace to `tmp_path`.
   - For one session, have two workers wait before the lock, then acquire `session_lock`,
     reload inside it, update different top-level synthetic marker keys, and atomically
     save. Assert both keys.
   - For one queue, have two workers wait before the lock, then use `queue_transaction`
     to append different synthetic jobs. Assert both jobs and valid JSON.
   - Also monkeypatch `os.replace` to fail on one attempted save and assert the prior
     valid session/queue document remains byte-for-byte readable. Keep all assertions
     in this one collected test.
