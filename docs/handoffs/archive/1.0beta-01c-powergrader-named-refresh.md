# 1.0beta slice 01c — PowerGrader named assignment refresh

Status: **GREEN — accepted relative to verified baseline** (archived on closure)

Risk: **medium** — changes the freshness source for PowerGrader session creation
(read path only); every grading write stays live and untouched.

Depends on: 1.0beta-01b accepted (relies on membership-filtered reads); benefits from 01a.

## Teacher-visible result

Starting a PowerGrader session for one text-entry assignment refreshes only that
assignment's submissions. Today it runs a whole-course delta — all assignments, all
recent submissions, plus New Quiz metadata — so starting one session in a large course
pays for the entire course. Target: focused refresh ≤15s median (vision §16.1), with zero
New Quiz metadata calls when opening a text assignment.

## Background (established truth)

`_mirror_session_submissions` (`api/powergrader/canvas_fetch.py:42`) calls
`mirror_service.sync_now(course_id)` (line 53) → `sync.delta_pass` → whole assignment
collection + course-wide submitted/graded-since submissions + `new_quizzes.sync_metadata`
(`api/mirror/sync.py` ~159-191). Vision §21 item 2; target behavior §11.4 and Program 6.
This slice delivers the delta-then-disk replacement for text entries only.

Expected facts:

- The mirror already fetches course submissions with Canvas query filters and merges
  idempotently via `merge_submissions`; a per-assignment submissions endpoint fetch
  (`/api/v1/courses/{c}/assignments/{a}/submissions`) can be normalized by the same
  `normalize_submission` allowlist.
- The per-assignment mirror projection deliberately does not persist nested Canvas `user`
  objects; PowerGrader gets display names from the local roster. A cold or incomplete roster
  must therefore preserve the exact live fallback, never degrade student names to ids.

If per-assignment submission responses lack fields the course-level fetch provides

## Locked design for this slice

### 1. New focused acquisition: `sync_assignment_submissions(course_id, assignment_id)`

**Placement ratification:** implement this as a pure
`sync_assignment_submissions(course_id, assignment_id, *, canvas_get_all, root=None, now=None)`
function in `api/mirror/sync.py`. It must call only the per-assignment endpoint with
`per_page=100` and `include[]=submission_history`. Do not request
comments, assignment, or user because the existing normalizer does not retain them. On a
transport failure, keep the existing submission document and course `_sync` document fully
unchanged; return an in-memory failure signal for the caller's live fallback. The existing
Canvas client already records its allowlisted, sanitized transport event in the operational
log. This slice must not misuse a course-wide pass envelope or introduce a persisted scope
envelope; that remains Program 1 coordinator work.

Add to `api/mirror/sync.py`: fetch
`/api/v1/courses/{course_id}/assignments/{assignment_id}/submissions` with the ratified
delta-compatible parameters above, normalize through the existing allowlist, and
commit via `merge_submissions` for that assignment only. Rules:

- No assignment-collection fetch, no other assignments, no roster, no New Quiz metadata.
- On error: last-good stays, no watermark movement, sanitized failure recorded — design
  law 5.10. This focused refresh never advances course-level delta watermarks (it is
  narrower than a delta; claiming delta coverage would be dishonest).
- Attempt history remains append-preserving exactly as `merge_submissions` does today.

### 2. PowerGrader switches to the named refresh

**Placement ratification:** `canvas_fetch._mirror_session_submissions` imports the pure sync
function and supplies its existing `_canvas_get_all` seam; do not add a `mirror_service`
wrapper or change manual/heartbeat behavior. After the focused sync and disk read, serve a
non-empty mirror result only when every returned `user_id` resolves through the existing local
roster; otherwise return the ordinary fallback signal so the current exact live submission read
provides Canvas `user` objects. An empty result remains servable without a roster.

`_mirror_session_submissions` calls the new focused acquisition instead of
`sync_now(course_id)`, then reads `assignment_submissions` from disk as today. The
existing fallback ladder (live fetch when the mirror path can't serve the session) is
unchanged and remains the safety net.

### 3. Text entries only

This path serves the existing text-entry delta-then-disk lane. Upload/media evidence
lanes and New Quiz sessions keep their current acquisition unchanged (Program 6 owns
those).

### 4. `sync_now` untouched

Manual sync and heartbeat behavior do not change in this slice.
