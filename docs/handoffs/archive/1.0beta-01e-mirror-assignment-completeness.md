## Locked design

### 1. Add a narrow complete-collection transport seam

Keep `_canvas_get_all(path, params, timeout)` unchanged for all existing callers. Add one private
companion in `api/webui/canvas_client.py`, named clearly as a complete collection seam, with the
same request arguments and an explicit three-value result:

```python
(rows, error, complete)
```

- `complete` is `True` only after every response was HTTP-successful, each response root was a
  JSON list, every opaque `rel="next"` link was followed, and a terminal response had no next
  link.
- A valid one-page or valid empty list is complete. Do not use a record count as proof.
- A transport/status/JSON failure, non-list root, or repeated next URL returns `complete=False`
  with a sanitized error; it must not expose or persist a raw URL, response body, or token.
- Follow Canvas's returned absolute next URLs as opaque values and clear initial query parameters
  after the first request. Detect a repeated next URL rather than looping forever.
- Factor only enough shared local code to avoid maintaining two different pagination parsers. Do
  not change `_canvas_get_all`'s legacy tuple contract or alter non-mirror callers.

This is a runtime receipt, not a persisted generic envelope and not Program 1 instrumentation.

### 2. Gate only destructive private assignment membership

Add an explicit injected `canvas_get_all_complete` argument to `sync.full_pass` and
`sync.delta_pass`; thread it through the first-sync fallback. `mirror_service` supplies the new
real client seam to heartbeat, Sync now, and the write-through `notify_course_changed` delta.
Existing `canvas_get_all` remains the injection for roster, submissions, and New Quiz metadata.

Use the complete seam only for `/api/v1/courses/{course_id}/assignments`:

- Require `complete=True`, `rows` to be a list, and every row to normalize through the existing
  assignment normalizer with a unique normalized ID before `_commit_assignment_index` is called.
- A complete empty list is authoritative: commit the empty index and retain the established
  large-shrink orphan-cleanup deferral. It must not be recast as an error.
- Any unproven/invalid collection returns `ok=False`, records the affected pass as failed with a
  stable sanitized code (`pagination_incomplete` or `invalid_response`), and leaves assignment
  index, submission files, New Quiz capability data, and watermarks unchanged. Because the
  assignment check occurs before other full/delta commits, it must not advance any collection or
  trigger New Quiz metadata work on that failed pass.
- Preserve ordinary network error classification for transport errors. Do not add `incomplete`
  to `_sync.v1.json` or change the current reader contracts in this slice.

Offline fakes must explicitly provide a complete receipt. They may not rely on a production
fallback that treats `(rows, error)` as complete. The focused assignment-submission refresh is
unchanged: it does not replace course membership and continues to use the legacy seam.

### 3. Preserve existing operational behavior

- A normally successful heartbeat, concluded daily core reconcile, manual Sync now, and
  write-through notify retain their behavior after receiving a true assignment receipt.
- Manual Sync now still performs its existing full/delta fallback and New Quiz cooldown bypass;
  an unproven assignment collection is a failed core sync, not a reason to fabricate a result.
- Do not alter course lifecycle acquisition/cadence, Current-course selection, status payloads,
  browser assets, or any Canvas write/preflight path.
