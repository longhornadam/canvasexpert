## Locked design for this slice

### 1. A narrow, student-free `course_context.v1.json`

Add a new versioned file under the existing per-course mirror directory. It is a scope record,
not an expansion of `_sync.v1.json`, and its strict allowlist is exactly:

```json
{
  "schema_version": 1,
  "course_id": "string",
  "state": "current | stale | unavailable",
  "last_success_at": "ISO-Z or empty",
  "last_attempt_at": "ISO-Z or empty",
  "error_code": "sanitized stable code or empty",
  "lifecycle": "current | concluded | unknown",
  "course_workflow_state": "string",
  "course_concluded": false,
  "course_end_at": "ISO-Z or empty",
  "term_end_at": "ISO-Z or empty",
  "enrollment_states": ["active | invited | completed | inactive"]
}
```

Do not retain course names, raw course/enrollment responses, person/section/role/SIS ids,
grades, URLs, or any unlisted field. A successful empty enrollment result is valid and yields
`lifecycle: "unknown"`. A failure retains the last-good lifecycle fields, changes only the
envelope to `stale` (or `unavailable` with no prior success), and never raises into scheduling.

### 2. One pure lifecycle acquisition and conservative classification

Add a focused pure helper/module in `api/mirror/` that accepts injected `canvas_get` and
`canvas_get_all`, `root`, and `now`.

- Fetch the single Canvas course with only `include[]=concluded` and normalize only the four
  course/term fields above.
- Fetch only the caller's enrollment for that course through
  `/api/v1/courses/{course_id}/enrollments`, using `user_id=self`, `per_page=100`, and
  `state[]` limited to `active`, `invited`, `completed`, and `inactive`. Normalize only the
  distinct allowed `enrollment_state` values, then discard the response.
- Classify `current` when any normalized enrollment is `active`; classify `concluded` only
  when at least one enrollment is `completed` or `inactive` and none is active; otherwise
  classify `unknown`. `course_workflow_state`, dates, and Canvas's `concluded` flag are
  diagnostic context only — they must never substitute for the teacher's enrollment state.
- Either transport/validation failure records its sanitized error in the context envelope and
  preserves last-good fields. It must not alter collection files, pass envelopes, watermarks,
  or the New Quiz capability document.

The executor must return RED, not substitute a roster-wide or all-course enrollment fetch, if
this per-course `user_id=self` request is not supported by the normal transport/test shape.

### 3. Scheduler behavior only; manual behavior stays live

`mirror_service.run_heartbeat_pass` ensures the context on first use and at most once per 24
hours. It uses a current or stale last-good `lifecycle: concluded` record to suppress the
ordinary fresh-course cadence:

- before the daily full reconcile is due, it runs no delta or roster pass;
- when the daily full reconcile is due, it runs that core reconcile but passes an explicit
  `skip_new_quiz_metadata=True` flag so no `/api/quiz/v1/` call occurs;
- `current` and `unknown` contexts keep today's full/delta/roster behavior exactly.

Add that explicit default-false flag to `sync.full_pass` and `sync.delta_pass`; when true it
returns a sanitized `new_quizzes` summary marked `skipped_lifecycle` without calling
`new_quizzes.sync_metadata`. No generic coordinator, priority queue, or per-scope retry system
is introduced here.

`sync_now` refreshes the context best-effort, then preserves its current full/delta fallback
and `bypass_new_quiz_cooldown=True` behavior regardless of lifecycle. It never suppresses
manual New Quiz probing. `notify_course_changed` stays unchanged.

Expose the strict context record in `mirror_service.status()` for configured courses; do not
change browser assets or make it a write gate.
