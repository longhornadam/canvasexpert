# Serve Course Info assignments from the current Course Catalog

Status: **RED; stopped**

Risk: **medium** - this changes a student-free display read only; Course Info’s private roster/email and group paths remain live.

Depends on: current `dev` after `5ef42de`

## Teacher-visible result

Course Info can display its assignment list from the current local Course Catalog without a
second Canvas assignment-collection request. Students, email, groups/memberships, and
modules retain their existing live behavior; a missing or non-current catalog falls back to
the present assignment request.

## Acceptance criteria

- [ ] `GET /api/course-detail` uses Course Catalog assignment records only when the catalog
  exists, its `assignments` scope is exactly `current`, and the records have the existing
  validated assignment shape. It returns the existing Course Info assignment fields
  (`id`, `name`, date-only `due_at`, `points`, `published`, `html_url`) without exposing
  catalog envelopes or new fields.
- [ ] On that current-catalog path the route makes no Canvas `/assignments` request. Its
  students/email, categories/groups/memberships, and modules calls remain live and unchanged.
- [ ] Missing, malformed, stale, incomplete, or unavailable catalog assignment data takes
  the existing live assignment path, including its existing error/empty-list behavior.
- [ ] No course catalog schema, assignment acquisition, Course Info browser/template text,
  Roster behavior, group ownership, or Canvas write/preflight behavior changes.
- [ ] The named acceptance gate below passes.

## Explicit non-goals

- Do not make Course Info roster/email, groups/memberships, or modules mirror-backed.
  Those require separate privacy/freshness decisions and, for modules, a published-state
  contract decision.
- Do not change the existing Course Info loading message, response schema, pagination,
  explicit email behavior, or any write path.
- Do not add an assignment-group scope; that is the next durable projection decision.

## Locked decisions

- The catalog assignments envelope is a display-only source only when its state is exactly
  `current`; every other state falls back to the existing Canvas collection call.
- Project only the Course Info fields from existing allowlisted catalog records. The route
  does not return catalog source, freshness, paths, warnings, or unapproved fields.
- Course Info continues to fetch teacher-requested email and group membership live; local
  assignment facts never authorize a mutation or placement decision.

## Execution result

**RED — no implementation changes.**

Preflight found a contract contradiction. Course Info's existing response requires
`html_url`, but Course Catalog's assignment allowlist (`ASSIGNMENT_KEYS`) excludes that
field and the Catalog contract's forbidden-material rule excludes Canvas transport URLs.
Thus catalog records cannot reproduce all six required Course Info fields without either a
Course Catalog schema/contract expansion or retaining a live Canvas assignment read; both
contradict the brief's explicit non-goals and locked current-catalog path.

Evidence: the preflight commands confirmed the live `/assignments` projection in
`api/webui/routes/courses.py` and the absence of `html_url` from
`api/course_catalog.py` `ASSIGNMENT_KEYS`; no named acceptance test was run because the
brief's required preflight fact is false. Changed files: this result only. Commit: none.

Senior decision: preserve the existing Catalog privacy boundary; do not add Canvas transport
URLs merely to migrate this Course Info display. A later Course Info redesign may make an
explicit safe response-shape decision.
