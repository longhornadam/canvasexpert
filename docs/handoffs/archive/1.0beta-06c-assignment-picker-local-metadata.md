# Serve the report/download assignment picker from Course Catalog

Status: **READY**

Risk: **low** - single read-only GET route; no writes, no Canvas mutation, existing live fetch
preserved as the fallback path.

Depends on: source HEAD `8eead15` (1.0beta-06b specced; independent of it — different files)

## Teacher-visible result

Opening the assignment picker on `/students/reports` (which lists every assignment so a
teacher can pick one to download/report on) makes **zero Canvas calls** when the course's
Course Catalog is current — it reads the exact same catalog data Course Info/Create's module
picker already trust. When the catalog isn't current, the picker falls back to exactly today's
live paginated fetch, unchanged.

## Background (read before writing code)

1.0beta-06a's non-goals deferred this exact migration, noting only that it "needs its own
dedicated investigation" before committing to it — that investigation is now done, in this
brief. `api/webui/routes/reports.py::list_assignments_full` (`GET /api/assignments-full`)
today does a raw, manually-paginated `requests.get` loop against
`{base}/api/v1/courses/{course_id}/assignments` (lines 33-56), then locally computes
`is_quiz`/`quiz_kind` (its own `_is_quiz`/`_quiz_kind` closures, lines 71-98) and an
`assignment_group_name` lookup from inline Canvas response data (lines 57-69), returning:
`id, name, submission_types, due_at (10-char date), points_possible, quiz_id,
assignment_group_id, assignment_group_name, is_quiz, quiz_kind, is_quiz_lti_assignment`,
sorted by `due_at` descending (lines 100-121).

Course Catalog's `normalize_assignment` (`api/course_catalog.py:340-365`) **already stores every
one of those fields** except the resolved group name: `id, name, points_possible, due_at (full
ISO string — a `[:10]` slice still yields the same date), submission_types, assignment_group_id,
quiz_id, is_quiz, quiz_kind, is_quiz_lti_assignment`, using its own `_quiz_classification`
helper (`api/course_catalog.py:322-337`) — the same detection logic
`list_assignments_full`'s `_is_quiz`/`_quiz_kind` reimplement independently today. The group
name is resolvable via `normalize_assignment_group` (`api/course_catalog.py:518-530`, has
`id`/`name`), exposed by `read_service.catalog_assignment_groups`. No Catalog schema change is
needed — this is a pure read-and-reshape migration.

### Deviations / design notes
- **Envelope variable names.** The brief's locked-decision prose illustrates the catalog
  reads as `assignments`/`assignment_groups`. I used `assignment_scope`/`group_scope`
  instead (matching the existing idiom in `api/webui/routes/push.py`'s
  `get_modules`/`get_assignment_groups`, e.g. `module_scope`, `group_scope`), because the
  function's live-fallback branch already has its own local `assignments = [...]` list
  variable a few lines down; reusing the same name for the envelope dict would have worked
  (Python allows the rebind since the branches return independently) but read confusingly.
  Purely a naming choice — no behavior difference.
- **The brief's teacher-visible framing names a picker that no longer exists.** The brief
  describes "the assignment picker on `/students/reports` ... which lists every assignment
  so a teacher can pick one to download/report on." I confirmed from source that
  `student_reports.html` (the `/students/reports` template) loads only
  `course_expert/student_reports.js` and `course_expert/portfolio.js` — neither calls
  `/api/assignments-full` at all (`student_reports.js` only hits `/api/students`,
  `/api/students/monitor`, `/api/student-packet/stream`; `portfolio.js` only hits
  `/api/open-folder`, `/api/portfolio/from-nq-csv`, `/api/portfolio/merged`). The picker the
  brief's background section describes (`api/webui/static/push/download.js`) was already
  retired before this brief — `api/tests/test_webui_template_contracts.py::
  test_download_work_runtime_is_retired` asserts that file no longer exists and isn't
  referenced from `course_expert.html`, and the large legacy test body exercising it below
  that assertion is dead code behind an early `return`. The **only** production consumer of
  `GET /api/assignments-full` today is `api/webui/static/gradebook/extensions.js` (the
  Gradebook "Extra Time" tab's assignment dropdown), confirmed by a repo-wide search. It
  reads only `asg.ok`, `asg.error`, and per-assignment `id`, `name`, `due_at` — every field
  this migration preserves identically. This does not contradict any locked technical
  decision (the route/function under migration, its envelope, and its acceptance criteria
  are all otherwise exactly as specified) and is not a stop condition, but the senior should
  know the brief's narrative framing describes a UI surface that predates its own retirement.
- **Two narrow value-level nuances surfaced during self-review item (a), neither a criteria
  violation:** (1) Catalog's `name` field is written through `_normalize_text` (collapses
  internal whitespace) at catalog-write time; the live path returns Canvas's raw `name`
  string untouched. For ordinary assignment names these are identical, but a name with
  irregular internal whitespace/newlines would render very slightly differently between the
  two paths. This is inherent to Course Catalog's existing storage contract (unmodified by
  this brief), not something newly introduced — the acceptance criteria call out exact parity
  for `due_at`/sort/`is_quiz`/`quiz_kind` specifically, not text-normalization parity for
  `name`. (2) Catalog's `_id()` helper (`str(value).strip()` when not `None`) versus the live
  path's `str(value or "")` idiom for `quiz_id`/`assignment_group_id` differ only in the
  practically-impossible edge case of a literal `0` ID (falsy under `or`, non-`None` under
  `_id()`) — not a realistic Canvas ID, flagged only for completeness.
