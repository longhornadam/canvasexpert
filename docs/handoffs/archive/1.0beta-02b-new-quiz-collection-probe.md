# Use one New Quiz collection probe before metadata items

Status: **GREEN; completed**

Risk: **high** - changes private New Quiz metadata acquisition and its 401/403 capability
circuit, but authorizes no grading, report, or other Canvas write.

Depends on: accepted `a576743`; baseline record in vision section 3.3

## Teacher-visible result

Refreshing metadata for several changed New Quizzes in an actively enrolled current course
uses one course-level New Quiz collection request plus only the necessary item requests.
Closed/concluded/restricted courses fail once into the existing bounded, honest restricted
state rather than fanning out per quiz.

## Acceptance criteria

- [ ] When at least one New Quiz needs metadata, `sync_metadata` makes one
  `GET /api/quiz/v1/courses/{course}/quizzes` collection request, makes no per-quiz metadata
  GET for collection-matched records, and fetches items only for records that need refresh.
- [ ] A collection `401`/`403` is one course/scope capability result: it opens/renews the
  restricted cooldown with sanitized evidence and makes no item or per-quiz fan-out calls.
- [ ] A successful collection proves the scope supported but does not hide record-level item
  failures; last-good item metadata and existing incomplete/unavailable semantics remain
  honest.
- [ ] An ordinary unchanged under-24-hour tick remains zero-call; manual/expired-restriction
  probe behavior uses the collection endpoint and can clear a restriction without inventing
  metadata.
- [ ] The named acceptance gate passes.

The executor reports evidence; the senior accepts only when every criterion holds.

## Locked decisions

- `GET /api/quiz/v1/courses/{course}/quizzes` is the metadata scope probe and source for a
  collection-matched quiz record. Its one successful result clears a prior restriction; its
  `401`/`403` is sufficient course/scope evidence for the existing 24-hour circuit because
  active enrollment gates this endpoint. Other collection failures are transient/invalid and
  do not open or renew the circuit.
- Evaluate metadata freshness before calling the collection. If every record is fresh and no
  manual/expired-restriction probe is due, preserve the existing zero-call behavior.
- For each stale assignment with exactly one collection record whose ID matches the assignment
  ID, fetch only `/items` and write through the existing metadata owner. A missing/duplicate
  collection match may use the existing per-quiz metadata GET as a narrow record-level
  compatibility fallback; it must not turn a collection 401/403 or transient failure into a
  fan-out.
- Collection success plus item-level failures remains `supported` with an honest incomplete
  metadata result. Collection failure leaves last-good data and does not prune metadata.
- Keep capability storage sanitized and schema-compatible. Update only current New Quiz
  acquisition/circuit wording in `docs/mirror.md` and the matching source comments.
