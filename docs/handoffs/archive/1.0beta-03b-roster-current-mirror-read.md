# Serve current Roster identity and sections from the private mirror

Status: **GREEN; completed**

Risk: **high** - Roster serves FERPA-protected identity/section facts, so stale or corrupt local state must never masquerade as current.

Depends on: current `dev` after `3332f40`

## Teacher-visible result

Opening Roster for a course with a current private roster mirror returns the same roster
rows without live Canvas reads for students or sections. Canvas groups remain live source
of truth, and absent/stale/corrupt mirror state uses the present live behavior unchanged.

## Acceptance criteria

- [ ] `GET /api/roster` uses current `store.read_roster(course_id)` students and sections
  before its existing live student/section fetches. It preserves the current JSON shape,
  vault merge/upsert, names, local settings, warnings, sort order, and no-SIS response rule.
- [ ] On the mirror-backed path, no Canvas students or sections request is issued; existing
  Canvas group/category loading remains live and unchanged.
- [ ] If the roster document is missing, invalid, or has any state other than `current`, the
  route uses its existing live student/section path and retains its existing Canvas-error
  response behavior. It must not serve partial last-good rows as current.
- [ ] No Roster mutation, group/membership fetch, local configuration semantics, mirror
  schema, scheduler, or browser/template behavior changes.
- [ ] The named acceptance gate below passes.

## Explicit non-goals

- Do not mirror or cache Canvas groups, group memberships, group-set selection, or any
  Roster write verification; group data remains a live operation surface.
- Do not add a freshness UI badge, background refresh, a new Roster projection, or a
  generic reader/adapter abstraction.
- Do not modify Course Info, Student Reports, MCP roster behavior, or unscoped live reads.

## Locked decisions

- `roster.v1.json` is a private read optimization only when its envelope state is exactly
  `current`. Missing/corrupt/unavailable/stale is an honest live fallback, not an error
  translation or a stale local display.
- Reuse existing `store.read_roster()` and its existing allowlisted student fields. Pass its
  student values through the existing Roster merge path so vault behavior remains intact;
  do not persist any additional field.
- The route continues to call `load_group_categories()` live after choosing the student/
  section source. No Canvas write is added or changed.
