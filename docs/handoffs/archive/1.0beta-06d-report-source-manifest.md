# Add a private source/freshness manifest to Student Reports and portfolios

Status: **READY**

Risk: **low** - purely additive, private, teacher-invisible sidecar file; no existing behavior
changed, no Canvas call added.

Depends on: source HEAD `fe0dd5b` (1.0beta-06a/06b GREEN; independent of 06c — different
files)

## Teacher-visible result

None directly — this is the private disclosure artifact the vision doc names for this batch,
not a rendered feature. Each generated report/portfolio folder gains one additional, private,
non-rendered sidecar file recording which courses' facts came from the local mirror versus a
live Canvas call, and how fresh the mirror was at generation time. No signed URLs, no absolute
filesystem paths, nothing rendered into the DOCX itself.

## Background (read before writing code)

Vision §11.7 (~lines 870-881): *"Reports should state source/freshness in their private
manifest. Do not copy signed URLs into reports."* §17.2 "Former Program 7" (~lines 1375-1390):
*"Include a private freshness/source manifest without signed URLs or private absolute paths."*

1.0beta-06a and 1.0beta-06b (both archived, GREEN) already gave both report generators a
per-course `used_local` boolean at the exact point they decide whether to read the private
mirror or fall back to a live Canvas fetch — `api/student_packet.py::build_packet` (per course,
inside its course loop) and `api/portfolio_service.py::build_merged_portfolios` (once, before
its student loop). Neither currently records or discloses that decision anywhere; this brief
adds that disclosure without changing either function's existing fetch/render behavior.

This is a distinct concern from `student_packet.py`'s existing `_manifest.json` (a
change-detection dedupe cache for `skip_unchanged`, keyed by a content signature + last-run
timestamp) — that file already exists, is untouched by this brief, and serves a different
purpose. This brief adds a **separate** sidecar file for source/freshness disclosure, so the
two concerns (dedupe vs. provenance) don't get tangled into one file's schema.

## Acceptance criteria

- [ ] A new `api/report_local_reads.py::local_course_freshness(course_id, *, root=None) ->
  dict` returns `{"source": "mirror", "synced_at": <the min of `private_assignments`'/
  `private_submissions`' `last_success_at`>}` when both envelopes are `state == "current"`
  (i.e. exactly when `local_course_submissions`/`local_course_submissions_by_user` would return
  non-`None` for the same course), else `{"source": "canvas", "synced_at": ""}`. This function
  does not change or duplicate the join logic in `_joined_course_records` — it reads the same
  two envelopes independently, purely for their freshness metadata.
- [ ] A new `api/report_local_reads.py::write_source_manifest(dest_dir, entries)` atomically
  writes/merges a private sidecar JSON (`_source_manifest.json`) into `dest_dir`, keyed by
  `course_id`, each entry `{"course_name": ..., "source": ..., "synced_at": ...,
  "generated_at": ...}`. Merging means: re-running a report for the same folder updates only
  the courses just processed, leaving any other course's prior entry untouched (matching
  `_manifest.json`'s existing merge-by-course-id convention). Contains no signed URLs and no
  absolute filesystem paths anywhere in its content.
- [ ] `api/student_packet.py::build_packet` calls `local_course_freshness(cid)` once per course
  (alongside its existing `used_local` determination) and accumulates one manifest entry per
  processed course; `write_source_manifest` is called once per student, into `stu_root`, after
  the course loop — written regardless of `skip_unchanged`/dedupe outcome, since freshness
  disclosure is independent of whether the packet content itself changed.
- [ ] `api/portfolio_service.py::build_merged_portfolios` calls `local_course_freshness(cid)`
  once (the function is single-course), and calls `write_source_manifest` once per student
  whose portfolio was actually written (i.e., skipped for a student whose run yields "no
  writing found" and continues without producing a DOCX — the manifest lives beside actual
  output, not for a student who received nothing).
- [ ] Neither function's existing fetch, render, or file-output behavior changes in any other
  way — `_info_blocks`, `_assignment_entries`, `_render_info_docx`,
  `portfolio.render_merged_docx`, `_manifest.json`'s dedupe semantics, and every existing
  06a/06b test all still pass unmodified.
- [ ] The named acceptance gate passes.

The executor reports evidence; the senior accepts only when every criterion holds.

## Locked decisions

- `local_course_freshness` and `write_source_manifest` both live in `api/report_local_reads.py`
  (the existing shared module), alongside `_joined_course_records`/`local_course_submissions`/
  `local_course_submissions_by_user`. `local_course_freshness` calls
  `read_service.private_assignments`/`private_submissions` directly (same as
  `_joined_course_records` does) with `max_age_hours=None` — an independent read, not derived
  from or dependent on `_joined_course_records`'s return value, so this brief never needs to
  change that function's existing contract.
- `write_source_manifest`'s merge behavior: read the existing `_source_manifest.json` at
  `dest_dir` if present (tolerate a missing/corrupt file exactly like `_manifest.json`'s
  existing `try/except` pattern in `build_packet`), update only the keys for courses in this
  call's `entries`, write back atomically (same `json.dump(..., indent=2)` style already used
  for `_manifest.json`).
- `generated_at` is the same `datetime.now().isoformat(timespec="seconds")` value already used
  for `_manifest.json`'s `last_run` field — reuse that exact call shape, don't invent a second
  timestamp convention.
- `source` values are exactly the two literal strings `"mirror"` and `"canvas"` — no other
  vocabulary.

### Deviations / design notes
- **`local_course_freshness` is called unconditionally per course iteration in
  `build_packet`** (right after computing `used_local`), but the resulting
  `manifest_entries[cid]` is only populated after the course is confirmed processed
  (`any_course = True`, i.e. `subs` non-empty). This satisfies both the brief's literal
  placement instruction ("alongside the existing `used_local` determination") and the
  "one entry per **processed** course" / "no entry for a course that produced no
  output at all" rule — the extra local-only read for an unprocessed course is
  side-effect-free (no Canvas call, no file write) and not worth branching around.
  Not a deviation from any locked decision, just the resolution of how the two
  brief-stated placements compose; flagged here for visibility per this brief's own
  YELLOW-adjacent note about the "no entry for a course with no output" question.
- **`generated_at` is computed per course-entry inline** (`datetime.now().isoformat(
  timespec="seconds")`), matching `_manifest.json`'s existing `last_run` call shape
  exactly, rather than being computed once per student/run and threaded through. This
  mirrors the precedent's own per-course-iteration placement of that same call; the
  values are for local disclosure only and no test or acceptance criterion requires a
  single shared timestamp across a student's courses.
- No senior decision needed; no criterion required narrowing.
