Status: **ACCEPTED**

Risk: **medium** — corrects student-free Course Catalog membership after a proven read-only
Canvas collection result. No private-mirror change, Canvas write, credential, UI, or live-data

## Teacher-visible result

When Canvas confirms that a Current course has no assignments or no modules, the local Course
Catalog accurately shows that empty scope instead of indefinitely showing deleted items. If a
later acquisition is incomplete or fails, the last-good catalog—including a legitimate empty
scope—remains readable and is labeled stale rather than unavailable.

## Locked design

### 1. Reuse the 01e receipt only for top-level catalog membership

Keep `canvas_get_all` for the existing bounded module-item fallback. Add a required explicit
`canvas_get_all_complete` argument to `refresh_catalog`, then route it only to the top-level
assignments and modules acquisitions. The Current-course refresh route injects the existing
`_canvas_get_all_complete` beside its unchanged legacy client.

- Require a true receipt and a list root before top-level assignments or modules may replace
  their persisted records.
- Receipt transport failure, `complete=False`, or non-list root produces the existing
  last-good-safe failure shape with stable sanitized `pagination_incomplete` or
  `invalid_response` codes (ordinary transport codes retain their existing mapping).
- Do not add a legacy fallback, persistent receipt field, coordinator, or new client function.
- Keep Catalog schema version and paths at v1: the persisted shape is unchanged; this is a
  correctness clarification of values v1 already permits.

### 2. Make proven emptiness authoritative, but retain successful emptiness safely

For both top-level scopes:

- A `([], None, True)` receipt writes `state: current`, the new attempted/success timestamp,
  empty records of the existing type (`{}` for assignments, `[]` for modules), and an empty error
  code. An empty modules scope must not start module-item fallback work.
- Subsequent failed/incomplete acquisition retains those empty records and returns `state: stale`
  because a prior successful acquisition exists. Determine prior success from a valid non-empty
  `last_success_at`, not record truthiness.
- Keep atomic canonical/previous Catalog behavior unchanged. After a successful clear, the new
  canonical file is authoritative; the previous file remains rollback/corruption recovery only.
- Preserve the existing independent-scope merge: a failed assignment scope cannot block a
  complete modules clear, and vice versa.

Do not alter current handling of non-empty partial invalid records or module-item fallback
incompleteness in this slice. Those are distinct completeness decisions, not permission to
revise broader Catalog normalization here.

### 3. Update the durable contract and preserve consumers

Update only `docs/contracts/course-catalog-contract.md` so it accurately says a fully
successful, fully paginated empty top-level collection is current and authoritative; failures or
unproven collection reads retain last-good records. Keep the exact allowlists, forbidden fields,
v1 filenames, Current-course gate, disk-only GET, and public projection shape unchanged.

`public_projection(...)["available"]` may correctly become false when both current scopes are
empty. Do not add special UI copy or change browser assets.
