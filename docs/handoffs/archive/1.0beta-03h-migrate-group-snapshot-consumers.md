# Route Create groups and Home roster warnings through the private group snapshot

Status: **GREEN; completed**

Risk: **high** - private membership IDs influence teacher-facing grouping/warnings; unavailable state must be honest and no local read may authorize a write.

Depends on: current `dev` after `ab1789e`

## Teacher-visible result

The Create differentiated-quiz group picker and Home roster warnings reuse a fresh private
group snapshot instead of independently performing the category/group/membership fan-out.
When the snapshot is unavailable, each preserves its existing live fallback behavior.

## Acceptance criteria

- [ ] `GET /api/groups` returns its existing category/group/member-ID JSON from a fresh
  `groups.v1.json` without invoking `load_group_categories`; missing/stale/corrupt state
  retains the existing live loader/error behavior and seeds the snapshot only after success.
- [ ] `roster_warnings.scan_course()` uses a fresh groups snapshot with no live group endpoint
  calls, while retaining its existing live group fallback when the snapshot is unavailable.
  It does not expose membership IDs/names in its findings.
- [ ] Student/roster sourcing, group mutation/preflight/verification, browser assets, group
  schema, cadence, and snapshot invalidation are unchanged. The named gate passes.

## Explicit non-goals

- No Course Info migration, no new read-service abstraction, no scheduler/transport change,
  no write-path change, and no removal of the existing live fallback.

## Locked decisions

- Reuse `store.groups_are_current(..., max_age_hours=24)` and `groups_for_roster`; do not
  create another cache shape. Snapshot use is display/derived-warning input only.
- Home live fallback remains its existing deadline-bounded transport. Create's fallback
  remains `load_group_categories`; both may seed only successful normalized results.
