# Coordinate one current-course assignment acquisition

Status: **GREEN; completed**

Risk: **high** - one read-only Canvas receipt will update both a student-free projection and
private mirror assignment membership; no Canvas mutation is authorized.

Depends on: source HEAD `5059b26` plus accepted slices 01b–01g

## Teacher-visible result

A current-course Course Catalog refresh performs one complete assignment-list read while
updating both local assignment projections safely; it does not add an extra Canvas fetch or
make a Catalog refresh a write preflight.

## Acceptance criteria

- [ ] One allowed `POST /api/course-catalog/refresh` requests the Canvas assignment
  collection exactly once and feeds that same in-memory receipt to the Catalog and private
  mirror assignment-membership consumers.
- [ ] A proven complete valid list, including a proven complete empty list, updates both
  projections with their existing rich/student-free and slim/private schemas respectively.
- [ ] An unproven, transport-failed, or invalid receipt never destructively changes private
  mirror membership; Catalog retains its established last-good/incomplete semantics.
- [ ] The Catalog GET remains disk-only and Current-course-gated; no raw Canvas row, student
  data, URL, or credential reaches the Catalog, response, log, or new persistence format.
- [ ] The named acceptance gate passes.

The executor reports evidence; the senior accepts only when every criterion holds.

## Explicit non-goals

- Do not create a general coordinator, typed read service, registry, cache, background job,
  cross-projection transaction, or new endpoint.
- Do not coordinate heartbeat/full/delta passes with Catalog refresh beyond reusing the narrow
  acquisition helper; module/groups/rubrics/submissions/New Quiz acquisition stays unchanged.
- Do not alter Catalog schemas/allowlists, mirror submission/roster passes, lifecycle/circuit
  behavior, Current-course policy, Canvas writes, or browser assets.

## Locked decisions

- Add one private `api/assignment_collection.py` helper that obtains the complete assignment
  collection and returns only the in-memory `(rows, error, complete)` receipt. It persists
  nothing, normalizes nothing, and is an immediate two-consumer seam rather than a framework.
- `course_catalog.refresh_catalog` may accept an already-acquired receipt; without one it
  preserves its present standalone acquisition behavior. Catalog normalization remains its
  owner.
- Add a mirror-sync receipt-application helper that validates with the existing mirror
  normalizer/complete-receipt rules before `_commit_assignment_index`; it performs no Canvas
  call, no pass-envelope/watermark mutation, no submissions sync, and no New Quiz work.
- The existing current-course Catalog refresh route is the one immediate coordinated consumer:
  acquire once, refresh Catalog, then apply the same receipt to mirror membership. The two
  projections remain independently durable: a local failure in one must not fabricate success
  or roll back the other.
- Update only the `Acquisition and writes` contract paragraph and current `docs/mirror.md`
  behavior text to state the coordinated in-memory receipt and its non-transactional boundary.
