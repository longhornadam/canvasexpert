# Typed CanvasMirror read spine and immediate adapters

Status: **GREEN; accepted**

Risk: **medium** - shared routine read semantics change, but no persistence schema, Canvas
command, credential, or student-data boundary may widen.

Depends on: current `dev` at `b7623e2`; preserve the existing dirty documentation worktree.

## Teacher-visible result

Routine local reads expose one honest source/state/time envelope instead of each consumer
inventing freshness behavior. Existing Catalog, Create picker, MCP catalog, Web UI helper,
and Work behavior remain local-first with their current explicit live fallbacks; no write
path can obtain authority through this service.

## Acceptance criteria

- [ ] A versioned runtime-only Canvas read contract and `api/mirror/read_service.py` expose
  exact typed scopes for private roster/groups/assignments/submissions and student-free
  Catalog assignments/modules/assignment-groups, always with `records`, source, state,
  timestamps, capability, generation, and sanitized error fields.
- [ ] `local_display` and `offline` are disk-only; stale local state is labeled rather than
  hidden. The contract names the remaining intents but `read_service` does not create a
  generic Canvas caller for them.
- [ ] `api/mirror/queries.py`, `api/webui/mirror_reads.py`, and the Work provider compatibility
  shim consume the service while preserving their public APIs, fresh-mirror zero-live behavior,
  and stale/error live fallback behavior.
- [ ] The Create module/assignment-group endpoints and MCP local assignment lookup consume
  the Catalog scopes through the service without widening the Catalog's output or privacy
  allowlist.
- [ ] The named acceptance gate below passes.

## Explicit non-goals

- No mirror, Catalog, group, roster, or submission persistence-schema migration; Catalog
  validation continues to reject unknown persisted fields.
- No coordinator, queued refresh, generic live fetch, authoritative-live, focused-current,
  diagnostics, write preflight, mutation, verification, or receipt migration.
- No new scope, Course Info migration, Gradebook change, PowerGrader behavior change, or
  removal of compatibility shims beyond this batch's callers.

## Locked decisions

- `api/mirror/read_service.py` is a local projection reader, not an HTTP client. Its v1
  envelope has `course_id`, `scope`, `state`, `capability`, `source`, `last_success_at`,
  `last_attempt_at`, `canvas_observed_at`, `retry_after`, `generation`, `error_code`, and
  `records`; all envelope fields are computed at read time and never added to Catalog files.
- Scope names are physical-domain explicit: `private.roster`, `private.groups`,
  `private.assignments`, `private.submissions`, `catalog.assignments`, `catalog.modules`, and
  `catalog.assignment_groups`. `records` is a copied list; no cross-domain joined view exists.
- A configured age limit may derive returned `state: stale` without discarding last-good
  records. Existing helper/shim fallback policy stays outside the service and keeps using its
  established injected Canvas functions. Commands never import this service for authority.
- Catalog scopes adapt validated `read_catalog()` output only; they retain its student-free
  contract, warning/recovery behavior, and no-live-read rule. Runtime `generation` is opaque
  and based only on projection identity/version and last-success metadata; absent observation
  data remains empty rather than inferred.
