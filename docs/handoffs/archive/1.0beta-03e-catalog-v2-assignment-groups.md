# Add a versioned assignment-group Catalog scope for Create

Status: **GREEN; completed**

Risk: **medium** - this evolves a durable student-free local schema and its atomic/last-good read behavior; it does not change Canvas writes.

Depends on: current `dev` after `3280cbe`

## Teacher-visible result

After a Course Catalog refresh, Create’s assignment-group picker can use the current local
course structure without a Canvas call. A missing, old, incomplete, stale, or unavailable
scope retains the existing live picker fallback. Every operation still resolves the selected
group live before writing.

## Acceptance criteria

- [ ] Catalog v2 persists an independently enveloped, student-free `assignment_groups`
  scope with exactly ordered `id`, `name`, `position`, and numeric `group_weight` records.
  Complete empty collections are current/authoritative; failed, incomplete, duplicate, or
  invalid collections retain valid last-good records with the existing sanitized state rules.
- [ ] Refresh acquires the complete assignment-group collection alongside existing Catalog
  work and writes validated `catalog.v2.json` atomically. It never writes or mutates Canvas.
- [ ] `read_catalog()` prefers valid v2 canonical/previous state, but continues to read a
  valid v1 canonical/previous document for existing assignments/modules. V1 is a read-only
  compatibility fallback and reports assignment groups unavailable; refresh never fabricates
  or rewrites a v1 document.
- [ ] `GET /api/assignment-groups` uses only a valid, exactly-current v2 local scope and
  returns its existing `{ok, groups:[{id,name}]}` shape with zero Canvas call. Every other
  state/version/malformed shape takes the current live path and preserves its error behavior.
- [ ] `GET /api/course-catalog` exposes sanitized assignment-group scope state/records
  consistently with the existing Catalog public projection; no response includes raw Canvas
  data, URLs, paths, credentials, or private/student fields.
- [ ] The durable Catalog contract and current mirror documentation describe actual v2/v1
  compatibility and the Create picker boundary. The named acceptance gate below passes.

## Explicit non-goals

- No gradebook configuration/late-policy scope, assignment-group mutation, weighted-grade
  calculation, group membership projection, generic coordinator, or background scheduler.
- No migration or mutation of `catalog.v1*.json`, no merging competing files, and no
  assignment/module schema change beyond v2 coexistence.
- No change to operation preparation, write preflight, live group resolution, browser assets,
  or Course Info.

## Locked decisions

- V2 files are `catalog.v2.json` and `catalog.v2.previous.json`; a refresh writes only v2.
  `read_catalog()` tries validated v2 canonical then v2 previous before the existing v1 pair.
- The assignment-group allowlist is exactly `id`, normalized `name`, integer `position`, and
  numeric `group_weight`. Order records by `(position, id)`. Unknown fields never persist.
- Assignment-group membership replacement requires a proven complete collection. Reuse the
  Catalog's existing sanitized envelope/last-good semantics; do not invent another state
  vocabulary or metrics layer.
- The picker may display local group names only. Operation adapters resolve live Canvas group
  identity/name and perform existing drift/preflight checks at execution time.
