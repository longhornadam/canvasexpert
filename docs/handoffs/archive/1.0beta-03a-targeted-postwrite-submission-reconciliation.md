# Target post-write reconciliation to the submission delta

Status: **GREEN; completed**

Risk: **high** - this changes how private submission/grade state converges after a Canvas write, though it performs no Canvas write itself.

Depends on: current `dev` after `9a99d00`

## Teacher-visible result

After a CanvasExpert write, the local mirror promptly refreshes the changed submission
facts without also fetching course structure or New Quiz metadata. A targeted refresh
never makes the broader mirror state look current when it has not completed a full delta.

## Acceptance criteria

- [ ] `notify_course_changed()` invokes the named `submissions.course_delta` refresh, not
  `sync.delta_pass()`; with established watermarks it issues exactly the existing
  submitted-since and graded-since collection requests, merges their rows
  idempotently, and performs no assignment or New Quiz request.
- [ ] This named refresh does not advance or record the general `delta` pass/watermarks.
  If watermarks are absent it makes no Canvas request and reports an honest
  `requires_full` outcome; if either submission request fails it reports failure without
  a false current/success claim or a partial merge.
- [ ] Its compact return summary identifies `submissions.course_delta` and provides only
  sanitized operational evidence: logical collection request count, non-negative duration,
  changed-row count, and touched-assignment IDs. It persists neither a metrics schema nor
  private response content.
- [ ] Existing heartbeat/manual `delta_pass()` behavior remains unchanged, and all current
  notification guards (token, enabled setting, workspace, fire-and-forget behavior) remain.
- [ ] The named acceptance gate below passes.

## Explicit non-goals

- No generic coordinator, scope registry, queue, coalescing, UI/status change, or durable
  per-scope metrics format. Those need multiple consumers and a later contract decision.
- No assignment-specific PowerGrader refresh work (already owned by 01c), no structure
  reconciliation, and no New Quiz metadata/response work.
- No change to Canvas write, preflight, receipt, retry, or pass-envelope semantics; no
  broad API-suite checkpoint.

## Locked decisions

- Add one narrow internal sync entry point named `submissions.course_delta`; it is a
  course-level overlapping submission delta using the existing two queries and merge
  semantics. It is deliberately not a replacement for `delta_pass()`.
- A targeted result is in-memory operational evidence only. `logical_requests` counts
  logical collection-client calls, not physical paginated HTTP requests; byte measurement
  is deferred rather than guessed.
- Both queries must succeed before any merge. The prior full/delta watermark remains the
  source window and is never advanced by this scope, so a later ordinary delta safely
  reconciles all scopes.
- Keep private data confined to existing mirror storage. Do not log response bodies,
  student fields, tokens, URLs, or filesystem paths.
